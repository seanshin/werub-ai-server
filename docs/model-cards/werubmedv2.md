## 2. 학습 절차 (Training Procedure)

### 2.1 하이퍼파라미터 (`training/medical_config.yaml` 원문)

| 항목 | 값 | 항목 | 값 |
|---|---|---|---|
| 방법 | QLoRA (4bit NF4) | epochs | 3 |
| LoRA rank (r) | 32 | batch size | 1 |
| LoRA alpha | 32 | gradient accumulation | 16 (유효 배치 16) |
| LoRA dropout | 0.05 | learning rate | 1.0e-4 (warmup ratio 0.1) |
| max_seq_length | 1,024 | 하드웨어 | RTX 5080 16GB 단일 |

### 2.2 학습 실행 기록

- 러닝타임 ~2분(GPU 로그 `logs/train_v2.log` — 소규모 데이터라 짧음), loss **2.38 → 0.70**
  (v1 대비, 커밋 42bf678 기록).
- 파이프라인: `training/prepare_medical_data.py`(수집·정규화) →
  `training/train_medical.py`(QLoRA) → merge → GGUF 변환 → `ollama create`.
- 알려진 학습 인프라 제약(재현 시 참고): 16GB VRAM에서 batch=1·seq 1024 필수,
  merge는 CPU 경로(메모리 제약), F16 중간 산출물은 배포 후 폐기(30GB).

### 3.2 v1 53건 (선행 — v1 카드 참조)

서버 `medical_consultations` 추출분(학습 시점 구성=데모·시드 데이터 — 2026-06-23 전면
보안 감사에서 라이브 PHI 0 확인) + 수동 골드(medical_gold.jsonl) + 합성. 태스크별
스냅샷 미보존(파이프라인 스크립트·설정으로 재현 가능).

### 3.3 개인정보·인구통계

- **실환자 식별정보 미포함** — 데이터는 약물 인허가 정형 필드의 템플릿 변환과 형식
  예시. 학습 시점 상담 테이블은 데모·시드 구성(§3.2 감사 근거).
- **인구통계 구성: 해당 없음** — 환자 코호트 데이터가 아니므로 인구집단 분포 자체가
  존재하지 않음. 인구집단별 성능 특성은 기반 모델(Qwen2.5)을 승계하며, 파인튜닝이
  특정 집단을 표적·배제하지 않음(상류 카드의 편향 논의 참조).

## 5. 의도된 용도 / 범위 외 / 한계

- **의도**: 한국어 의료 문서 보조 — SOAP 요약·감별진단 JSON 구조화·약물 정보 Q&A의
  **형식·스타일 적응**. 자문 보조(최종 판단=의료인)·면책 문구 강제.
- **범위 외**: 단독 진단·처방 결정 · 환자 직접 노출 단독 응답 · **트윈 허가 대상 기능
  경로**(predict·DUR·ADR·reference·explain·translate — 실측상 미관여,
  `mfds-model-inventory.md` §2).
- **한계**(정직 명시):
  1. 232건 소규모 = 형식 적응 목적. **의학 지식은 기반 모델+프로덕션 RAG(식약처·법령
     정본 grounding)에 의존** — 본 모델 단독 지식 신뢰 금지.
  2. 독립 표준 벤치 미측정(§4).
  3. 합성 데이터 중심이라 실제 임상 서사·구어 변이 커버리지 좁음.
  4. 기반 모델 상류 한계 승계(HF `Qwen/Qwen2.5-7B-Instruct` 카드 참조).
