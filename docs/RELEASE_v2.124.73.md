# v2.124.73 — 한정 단서 결정적 부기 + `numbers_match` 기준 명확화 (폐루프 16)

> 2026-08-04 · `routes/medical_law.py` · `core/llm_judge.py` · 회귀 +11 (1207 passed)

배치 `checks_failed` 1위였던 **`accuracy.conditions_kept` 47%**를 드릴다운해 원인을 확정하고
처치했다. 함께 4위였던 `accuracy.numbers_match` 37%는 **원인이 전혀 달랐고**, 그래서 처치도
분리했다.

## 1. 드릴다운 — 두 지표는 원인이 다르다

### `conditions_kept` = 실제 탈락 (judge 위양성 아님)

가설을 순서대로 세우고 전부 측정으로 기각/확정했다.

| 가설 | 검증 | 결과 |
|---|---|---|
| judge 위양성 | 저장 답변을 시드만 바꿔 **N=8 재채점 × 5문항** | **40/40 False** — 완전 결정적, 노이즈 아님 |
| 근거 결손(검색 문제) | 근거 원문에서 단서 패턴 검색 | **5/5 문항에 단서 온전히 포함** |
| ⇒ 생성이 빠뜨림 | — | 확정 |

그리고 **단일 패턴**이었다. 실패 문항이 12개로 흩어져 보였지만 상위가 전부 보존기간
문항군(진료기록부·수술기록·간호기록부·검사내용·방사선·환자명부·처방전)이고, **의료법
시행규칙 제15조① 단서 하나**를 공유한다.

> 다만, 계속적인 진료를 위하여 필요한 경우에는 **1회에 한정하여** 다음 각 호에 정하는
> 기간의 범위에서 그 기간을 **연장하여 보존할 수 있다.**

답변은 `제15조(진료기록부 등의 보존)` **조 전체를 인용 대목으로 제시**하고 기간만 말한다.
기준(`"인용한 대목에 한정 조건이 없으면 true"`)에 비추어도 위양성이 아니다.

### `numbers_match` = judge 기준 오적용이 다수

같은 방식으로 재채점하니 4/5가 실제 실패였으나, **judge 사유가 수치와 무관**했다.

| 문항 | judge 사유 | 실제 성격 |
|---|---|---|
| 진료기록 송부 | "진료기록전송지원시스템은 질문과 관련 없는 정보" | 관련성 |
| 전자의무기록 | "근거 일부가 번역 오류로 **정확한 수치 일치를 확인하기 어렵**" | **측정 불능** |
| 처방전 대리수령 | "**벌칙 정보가 제공되지 않았**" | 완전성 |
| 사본 발급 | "조항 번호와 내용이 일치하지 않아" | 수치 ⭕ |

특히 "확인하기 어렵다 → False"는 **v2.124.16에서 봉합한 메타 진술 감점과 같은 구조**
(측정 불능을 실패로 계산)다.

## 2. 처치 ① — 한정 단서 결정적 부기 (`routes/medical_law.py`)

규칙 4·5가 이미 한정조건 보존을 지시하는데 47%가 실패하므로 **지시 강화는 후보에서
제외**했다(반복 확인된 확률 위반 클래스). 근거에 있는 원문을 **결정적으로 추출해 부기**한다
— LLM 호출 0·창작 위험 0.

```
[인용 조문의 단서(근거 원문)]
- 제15조: 다만, 계속적인 진료를 위하여 필요한 경우에는 1회에 한정하여 …
```

- **조 귀속은 괄호 제목이 붙은 헤딩으로만** — 🐞 첫 구현이 본문 교차참조
  (`법 제22조제2항에 따른`)를 헤딩으로 오인해 제15조① 단서가 **제22조로 붙었고 게이트가
  통째로 무발동**했다. v2.124.9에서 이미 겪은 함정("표제는 조-only 토큰만")이 재발.
- **판정은 단서별 내용 커버리지** — 답변 전체의 '다만' 어휘 유무로 보면 *다른* 단서를
  빠뜨린 경우를 놓친다(재현율 0.50→0.70 실측).
- 답변이 **인용한 조**의 단서만. 질의 풀 40문항 중 **98%가 근거에 단서를 갖고 문항당 최대
  10개**라 무차별 부기는 오염이다.
- `/ask`·`/ask/stream` **양쪽 적용**. 스트림은 부기분을 토큰으로도 흘려보내 누적 텍스트와
  `done.answer`가 어긋나지 않게 했다.
- config `medlaw_clause_note`(기본 true)·`_coverage`(0.5)·`_max`(2) 무재배포 튜닝. 끄면 기존 동작.

**실측**(저장 답변 40문항, 기준=배치 `conditions_kept`): 임계 0.5에서 **정밀도 0.56·재현율 0.70**,
발동 25/40, 부기 평균 1.5건.

> ⚠️ **정밀도가 임계를 올려도 0.58에서 안 오른다** — 기준 자체가 우리가 고치려는 불안정
> 지표이므로 더 튜닝하면 과적합이다. 실효 검증은 **다음 배치의 `conditions_kept` 변화**로 한다.
> 이른바 FP 7건도 내용을 보면 실제 누락이었다(조건부인증 1년·휴업 1개월 미만 면제·제1호는
> 면허취소).

**라이브 검증**: 간호기록부→제15조 단서, 수술기록→제15조 단서, 무면허 벌칙→제27조 예외 2건,
의료법인 설립→제33조 예외. 전부 인용 조에 맞는 단서.

## 3. 처치 ② — `numbers_match` 기준 명확화 (`core/llm_judge.py`)

같은 파일 `consistent_register`가 이미 쓴 방식(기준 문구에 정상 케이스를 명시)을 따랐다.

> 답변이 제시한 수치(기간·금액·조문 번호)가 근거와 정확히 일치하는가 — **대조할 수치가
> 없거나 근거가 불완전해 확인이 어려우면 true**(측정 불능은 실패가 아님). **빠진 정보
> (완전성)나 근거의 관련성은 이 항목이 아니며** 해당 차원에서 판단한다.
