v2.125.3이 "같은 클래스 표면이나 실패 미관측"으로 남긴 `writing.py`의 나머지
`force_korean` 반환 지점들을 **셌다.** 세 곳은 깨끗했고, 두 곳은 **늘 깨져 있었다.**

## 1. 관측이 먼저 — 그리고 탐지기가 먼저

처치할 표면이 있다는 것과 그 표면이 실제로 실패한다는 것은 다른 말이다
(효과 미확인 처치 금지, v2.124.63). 그래서 먼저 셌다.

🔑 **결함을 세기 전에 탐지기를 통제군에 걸었고, 그 자기검증이 내 탐지기 결함을 잡았다.**

draft의 판정(`한글 + 40자 하한`)을 그대로 가져다 쓰면 안 됐다 — polish·translate는
*입력을 변환하는* 경로라 **짧은 입력에 짧은 출력이 정상**이다. 절대 하한 10자를 두자
통제군의 `"안녕 하세요"` → `"안녕하세요."`(6자)가 **붕괴로 집계**됐다.

| | |
|---|---|
| 그 탐지기로 셌다면 | polish·translate에 **없는 결함**이 생겼을 것 |
| 고친 뒤 | 절대 하한을 빼고 **입력 대비 비율(0.3배)** 로만 판정 |

📌 v2.125.3은 탐지기 **과소**계상(`의사|의료인`만 봐서 0/50)이었고, v2.124.94는
**과대**계상이었다. 이번엔 위양성 쪽이다 — **탐지기는 양방향으로 틀린다.**

## 2. 🔴 seo·evaluate — 간헐이 아니라 **늘** 그랬다

`raw` 폴백이 8/8. 호출자가 받는 것은 `meta_description: ""` · `keywords: []`인
**빈 결과인데 HTTP 200**이다. 로그에 흔적이 없다. 이 두 엔드포인트는 사실상
**동작한 적이 없다.**

### 부순 것은 모델이 아니라 우리 후처리다

라이브 원문을 열어 보니 LLM 출력 자체는 **멀쩡한 한국어 JSON**이었다.

```python
response = force_korean(response)       # ← JSON 문자열을 줄 단위로 거른다
result   = force_json(response, "raw")  # ← 구조가 이미 깨져 파싱 실패
```

`force_korean`은 **한글 없는 줄을 버린다.** JSON에서 그 줄이란:

```
 "keywords": [        ← 삭제
 "score": 70,         ← 삭제
 },  ],  }            ← 삭제
```

**구조 전부**다. 통제 비교:

| | 입력 | 출력 |
|---|---|---|
| 필터 먼저(현행) | 정상 JSON | `{"meta_description": "", "keywords": [], "raw": …}` |
| 파싱 먼저(처치) | 같은 JSON | 내용·숫자(`score: 65`)·불리언(`false`) 전부 보존 |

📌 **v2.124.50과 같은 클래스**다 — 그때는 같은 필터가 비전 경로의 **영문 OCR을 통째로
삭제**해 "모델이 빈 응답을 준다"로 보였다. *필터는 자기가 무엇을 지우는지 모른다.*

### 🔑 고칠 것은 필터가 아니라 순서였다 — 그 함수는 이미 있었다

`force_korean_json`(파싱 먼저 → **문자열 값에만** 필터)이 진작 있었고,
`medical_advanced.py`는 **10곳에서 줄곧 그렇게 쓰고 있었다.**
레포 전수 확인 결과 순서가 뒤집힌 곳은 **이 둘뿐**이다.

```python
result = force_korean_json(force_json(response, "raw"))
```

⚠️ **부수 효과**: 이제 영문 문자열 값은 살아남는다(종전엔 통째 삭제라 호출자가
아무것도 못 받았다). 어느 쪽이든 개선이지만 기록해 둔다.

## 3. 회귀 — 규칙이 아니라 **전제**부터 고정한다

`tests/test_writing_json_filter_order.py` **5건**.

- `test_filter_destroys_json_structure` — *필터가 JSON을 부순다*는 전제를 먼저 못 박는다.
  필터가 언젠가 구조를 보존하게 바뀌면 **이 테스트가 먼저 빨개져서** 아래 순서 규칙의
  근거가 사라졌음을 알린다(근거 없는 규칙만 남아 도는 것을 막는다).
- `test_correct_order_preserves_content` — 숫자·불리언은 문자열이 아니라 필터가 손대지 않는다.
- `test_json_fallback_still_reports_failure` — LLM이 진짜로 JSON을 못 냈을 땐 여전히
  `raw`로 정직하게 알린다. ⚠️ 순서를 고쳤다고 **실패를 감추면 안 된다**.
- `test_no_force_korean_before_force_json_in_writing` — **세 번째 지점**이 생기는 것을 막는다.
  이 결함은 200으로 나가 로그에 흔적이 없으니 사람이 눈치채는 경로가 아니다.
- `test_json_endpoints_use_force_korean_json`
