`routes/triage.py`의 두 지점에 v2.125.16이 이렇게 적어 두었다:

> "결과는 종전과 같다 — 바뀐 것은 **실패가 로그에 남는다**는 점뿐이다" (`:718`)
> "결과는 종전과 동일하고 **실패만 로그에 남는다**" (`:757`)

`routes/triage.py:11`에 정의해 두고 **파일 전체에서 한 번도 쓰지 않았다**.
즉 처치가 주장한 유일한 효과가 이행되지 않았고, HTTP 오류는 종전과 똑같이 조용히
`["기타증상"]`·`""`로 착지하고 있었다.

- 형제 지점은 실제로 이행돼 있었다 — `writing.py`는 `Error: {e}`를 호출자에게 돌려주고,
  `chat_memory.py`는 던지고, `orchestrator.py:1732`는 안내문으로 바꾼다(이 주석은 로그를
  주장하지 않아 참). **triage 두 곳만 결과·가시성이 둘 다 종전과 완전히 동일**했다.
- 처치: 결과는 그대로 두고 `logger.warning` 각 1줄. 호출자 계약(항상 리스트 / 빈 안내문
  허용)은 불변이다.

🔑 **릴리즈 노트가 코드보다 앞서 나간 경우**다. 이 레포가 가장 싫어하는 클래스라 별도로 센다.

## 2. T1-b — P5-1 잔여(triage 검증기·재시도): 사전 등록 후 **기각**

X11이 "P5-1 as-built 3/5 · triage 검증기·재시도 미이행 잔여"로 남긴 항목을 착수했다.
재시도는 LLM 호출을 최대 2회(각 timeout 15s) 늘리므로 **기준을 측정 전에 못 박았다**(규율 #3).

- 사전 등록: `docs/01-plan/references/triage-json-retry-preregistration-2026-08-26.md`
- 원자료 전문: `docs/01-plan/references/triage-json-retry-rawdata-2026-08-26.json`

| 지표 | 실측 | 등록 기준 | 판정 |
|---|---|---|---|
| a1 JSON 준수 실패율 | **10% (3/30)** | >5%면 전환율을 본다 | — |
| 재시도 전환율 | **0/8 (0%)** | <50% → 미적용 | **기각** |
| 반복 통제(동일 문장 5회) | 5/5 실패 · 재시도 0/5 전환 | — | 폭주가 **결정적** |

실패 모드가 예상과 달랐다. 형식 실수가 아니라 **배열을 쓰다 말고 중국어 잡담으로 폭주**한다:

```
["체중감소", "목枯燥，去掉最后一句及之后的内容，得到的答案是：
["체중감소", "목干燥后的答案为： …
```

`generate_with_validation`의 교정 system 접미사를 붙인 재시도도 **8/8 같은 방식으로 무너졌다**.
temp 0.1에서 5/5 재현 ⇒ 프롬프트 교정으로 잡히는 결함이 아니다.
⇒ **기획서에 적혀 있다는 것은 이행 이유이지 효과의 증거가 아니다**(규율 #4).

### 측정 절차의 결함도 기록한다

라운드 1은 후보 20건 중 **규칙 추출기가 10건을 잡아 유효 N=10**이었다 — 자격 필터가 표본을
반으로 줄일 것을 등록 시점에 예상하지 못한 **사전 등록의 결함**이다. 사건 1건으로 비율 기준을
적용하는 것은 무의미하므로 판정하지 않고 풀을 40으로 늘려 라운드 2에서 N=20을 채웠다.
**§3의 임계값은 손대지 않았다.** 라운드 2 설계 전에 라운드 1 원자료를 열어 본 사실도 기입했다.

## 3. 🔴 측정이 드러낸 진짜 결함 — 폴백이 폭주 잔해를 증상으로 내보냄

사전 등록 §1에 "쉼표 분리 폴백이 이미 평문을 건져낸다"고 적었는데 **틀렸다**. 폭주 응답에서
그 폴백은 잔해를 그대로 증상으로 내보내고, 이게 API 응답 `symptom_analysis.extracted_symptoms`에
실려 나간다:

| 입력 | 종전 출력 |
|---|---|
| 손발이 늘 차고 겨울엔 손끝이… | `['["손발冰冷"', '"手指变白"]', '["손발이 차다"', '"손끝이 하얗게 변함"]']` |
| 최근에 이유 없이 살이 빠졌고… | `['["체중감소"', '"목干燥后的答案为：', '["체重减轻"', '"口渴"] 更改为…', …]` |

**200인데 빈 결과** 클래스의 변종이다 — 응답은 200이고 필드도 비어 있지 않아 사람이 눈치채는
경로가 없다(반복 결함 클래스 #1).

**처치**: `routes/triage.py:_parse_symptom_list`
1. `force_json_array` 실패 시 응답 속 **JSON 배열 조각을 긁는다**(모델이 정상 배열 뒤에 잡담을 붙임)
2. 대괄호·따옴표 잔재 제거 (`'["체중감소"'` → `체중감소`)
3. **한자·가나가 섞인 항목만** 배제 · 중복 제거
4. 최종 방어선인 쉼표 분리에도 같은 정화를 건다(계약=항상 비지 않은 리스트)

**변형 비교**(원자료 35건 재사용 · LLM 재호출 0):

| 안 | 개선 | 퇴행 | 오염 잔존 | 통과 건 영향 |
|---|---|---|---|---|
| A — 한글 포함 요구 | 8 | 0 | 0/35 | `['olfaction loss']` → `['기타증상']` **1건 변화** |
| **B — 한자·가나만 배제(채택)** | 8 | 0 | 0/35 | **0건** |

B가 엄격히 우월해 채택했다. 영어 항목 삭제는 오염 제거와 달리 **근거가 없다** — 손대지 않는다.
⚠️ 다만 영어 증상명은 `_get_dept_recommendations`의 한국어 규칙과 매칭되지 않는다(별건·미측정).

거부 + 엣지 케이스 회귀 6. 부수 개선: `我不知道`처럼 한자만인 응답도 이제 `["기타증상"]`.

## 4-b. 라이브 검증 — T1-a가 배포 직후 실전에서 값을 증명했다

배포 후 `/api/medical/triage`에 측정에서 폭주했던 문장을 투입:

| 입력 | `extracted_symptoms` | 추천 |
|---|---|---|
| 최근에 이유 없이 살이 빠졌고 목이 마릅니다 | `['체중감소']` (오염 0) | 내과·내분비내과 |
| 손발이 늘 차고 손끝이 하얗게 변합니다 | `['기타증상']` ← **아래 참조** | (없음) |
| 냄새를 거의 못 맡은 지 두 달 | `['olfaction loss']`(영어 보존·설계대로) | (없음) |

🔑 두 번째 건의 `['기타증상']`은 파서 과잉 배제가 아니었다 — 같은 문장을 직접 3회 호출하니
파서는 3/3 `['손발이 차다', '손끝이 하얗게 변함']`을 정확히 뽑았다. 정체는 **Ollama 15초 read
timeout**이었고, **T1-a가 그것을 로그에 남겼다**:

```
[WARNING] triage 증상 LLM 추출 실패 (['기타증상']로 폴백):
  HTTPConnectionPool(host='localhost', port=11434): Read timed out. (read timeout=15)
```

오늘 이전이라면 **200 응답 + 그럴듯한 필드 + 로그 0줄**로 완전히 안 보였을 결함이다.
T1-a는 "결과가 안 바뀌는 처치"였지만 배포 몇 분 만에 실전에서 한 건을 드러냈다.
(원인은 게이트 직후 모델 스왑으로 14b 재적재가 15s를 넘긴 것 — §7의 VRAM 경합과 같은 뿌리.)
