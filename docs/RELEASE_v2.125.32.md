## 1. 먼저 **확정 가능한 것과 아닌 것**을 갈랐다

스키마는 상태코드와 달리 기계적으로 확정되지 않는다. 그래서 지어내는 대신 AST로
성공(2xx) 반환을 분류했다:

| 분류 | 건수 | 근거 |
|---|---|---|
| **정적 확정 가능** | **86** | 핸들러가 `jsonify({...})` **dict 리터럴**을 반환 → 최상위 필드명이 코드에 있다 |
| 정적 확정 불가 | 121 | `jsonify(result)`·`**` 확장 등 — 변수의 내용이 런타임에 결정 |
| 기타 | 9 | 라우트-핸들러 매칭 불가 |

## 2. 자동 생성 78건 — 이름은 코드에서, 타입은 추론되는 것만

필드 **324개** 중 타입이 정적으로 추론된 것은 **114개**(리터럴·`len()`·리스트/딕트 등).
나머지 210개는 **이름만** 싣고 타입을 비웠다 — 추측한 타입은 없느니만 못하다.

```yaml
        schema:
          type: object

            sessions: {type: array}      # 추론됨
            source: {}                   # 이름만 — 타입 미확정
```

## 3. 연동 표면 5건은 손으로 — core 함수까지 읽었다

카탈로그가 가리키는 23경로 중 스키마가 없던 **7건**을 확인해(둘은 ①에서 이미 해소)
나머지 5건은 **호출되는 core 함수의 실제 반환까지 읽어** 작성했다:

- `/api/medical-law/ask` · `/review` — 🔴 **`disclaimer` 필드를 스펙에 명시**했다.
  "법률 자문이 아니다"라는 고지가 **응답 필드로 나가는데** 스펙에 없으면 연동 화면이
  그 필드를 렌더하지 않는다. `has_evidence: false`가 판정 신뢰도 저하 신호라는 것도 적었다.
- `/api/notice/drug-substitution` — `core.drug_substitution.lookup`을 읽어
  `found`/`resolved_via`/`alternatives*` 구조와 **"양쪽 약가가 있을 때만 cheaper 판정"**을 명시.
- `/api/notice/fee-codes/stats` — `core.fee_codes.fee_stats`의 `{total, by_category}`.
- `/api/medical/cli/execute` — `confirm_required`가 **실행 전 확인 필요** 신호임을 명시.
- `/api/medical/knowledge/search` — `mode`가 실제로 쓰인 검색 방식을 되돌려준다는 점.

⚠️ **판정 정정**: 처음엔 카탈로그 23경로 중 "21건이 수동 필요"로 셌는데 **틀렸다** —
자동 생성 목록에 없다는 것뿐이고 **이미 스키마를 가진 것**이 섞여 있었다. 라이브 스펙으로
다시 재니 실제 결손은 **7건**이었다. 탐지기를 라이브 기준으로 다시 걸어 정정했다.
