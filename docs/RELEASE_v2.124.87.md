## 2. 🔴 `numbers_match` — 실패의 52%가 **증명된 위양성**

`v2.124.73`이 이 항목의 기준 문구를 고쳤다(*"대조할 수치가 없거나 확인이 어려우면 true —
측정 불능은 실패가 아님"*). 그런데 실패율이 38% → **62%로 올랐다.**

judge ↔ 결정적 계산을 40문항에서 대조했다:

```
일치            15
judge만 실패    25   ← 전부 이쪽
결정적만 실패    0
```

25건 중 **13건(52%)은 답변에 수치가 아예 없었다.** judge가 사유에 스스로 적었다:

> "답변에서 제시한 수치가 없어 이를 확인할 수 없어…"
> "답변과 근거 사이의 수치 일치 확인이 불가능하여 1점 감점"

**금지한 바로 그 행동을 그대로 하고 있다.** 나머지 12건은 수치가 있었고 **전부 근거에 실재**한다.

> 🔑 `v2.124.74`와 같은 결론이다 — **"무엇이 실제로 거기 있나"는 문구로 교정되지 않는다.**
> 그때 형식 2항목에 내린 판단이 수치 항목에도 그대로 적용된다.

**처치**: `numbers_grounded(answer, evidence)` 순수 함수로 이관(judge 값 덮어씀).
단위 붙은 수치만 대조하고 **조문 번호·개정일자는 제외**한다(`제15조`를 수치로 세면 전부 오판).
수치가 없으면 **True**. 근거가 없으면 **judge 값 유지**(무근거 덮어쓰기 금지).

### ⚠️ 정직하게 — 이건 변별이 아니라 회귀 가드다

배치에 적용하면 **0/40 실패**다. 즉 지금은 아무것도 잡지 않는다.

- **한계**: 근거 어딘가에 있기만 하면 통과하므로 **귀속 오류를 못 잡는다**
  (조문 A의 수치를 조문 B에 붙이는 것). 그건 충실도 축의 `contradicted`가 본다.
- **그래도 이관하는 이유**: 100% 노이즈인 체크는 `checks_failed` 순위를 왜곡해
  **작업을 잘못된 곳으로 보낸다**(실제로 `v2.124.73`이 여기 시간을 썼다). 침묵하는 체크는 중립이다.

> ⚠️ **추세 단절점(상향)**: `checks_rate`가 약 **+5%p**(25/480) 오른다.
> **품질 개선이 아니라 측정 교정**이다. 품질 지수도 같은 폭으로 상향된다.
