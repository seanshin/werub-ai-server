# v2.125.43 — Jev 어댑터 배선(P6-1 Phase 1): 키가 오기 전에 경계부터 세운다

기준 v2.125.42 · 기획 `docs/01-plan/features/P6-1-Decision-Confidence-And-Jev.plan.md` §6

## 0. 한 줄

Jev(TypeSafe System One) 어댑터·설정·**PHI 경계 회귀**를 배선했다. **기본 off이고 키가
없으므로 동작 변화 0.** 측정(관문 A0·§8 판정)만 운영자 키를 기다린다.

🔑 **순서가 중요하다** — 배선보다 경계를 먼저 세운다. 키가 생긴 뒤에 경계를 만들면,
그 사이에 누군가 의료 경로에서 부르는 배선을 넣어도 막을 것이 없다.

## 1. `core/jev.py` — 이 레포의 유일한 Jev 호출 지점

- 엔드포인트 `POST https://api.typesafe.ai/v1/systemone` · Bearer · **`jev-1.13.0` 고정**
  (`jev-latest` 금지 — 판정자가 조용히 바뀌면 추세선이 끊긴다. judge 교체 때 겪었다).
- **SDK 미사용** — `typesafe-sdk` 의존성을 추가하지 않는다. 계약이 단순해 이득이 없고
  의존성 추가는 arm64·CUDA 분리 이슈를 다시 만든다.
- **fail-open 불변식**: 미설정·미도달·캡 초과·파싱 실패·비허용 호출자 = **전부 `None`**
  (호출자 축 null). **예외를 던지지 않는다** — 외부 서비스 때문에 평가 배치가 멈추면 안 된다.
- **무성 실패 금지**: `None`을 줄 때마다 로그. 정상 상태인 '미설정'만 info, 나머지는 warning,
  **비허용 호출자는 error**(배선 오류라 조용히 넘어가면 안 된다).

### 공급사가 공개한 약점이 설계를 제약한다

| 약점 | 처치 |
|---|---|
| state가 클수록 정확도 하락(#5) | `jev_state_max_chars`(기본 6000)로 **자른다**(거절 아님) + 로그 |
| prompt injection 영향받음(#6) | 판정은 **사람 검토 트리거로만**. 자동 삭제·게이트 직결 금지 |
| `P(noul)` ≠ `1-P(not noul)`(#8) | 같은 명제를 긍정/부정 두 형태로 묻지 않는다(docstring 규약) |
| 레이트 "동적 조정 중" | 429/503은 **경계 있는 재시도** 후 축 null(§2) |
| 영어 우선 | **관문 A0**(한국어 N=12)로 비용 쓰기 전에 가른다 — Phase 2 |

## 2. 🔑 레이트 리밋과 일일 캡을 **갈랐다**

운영자 질문("토큰 리밋에 걸리면 대기했다가 후속 진행이 가능한가")에 대한 설계 답이다.
**둘은 다른 것이라 처치가 반대다.**

- **공급사 레이트(429·502·503·504)** = 초 단위 일시 현상 ⇒ **기다렸다 한 번 더 시도한다.**
  `Retry-After`를 존중하고, 없으면 1s·2s 백오프. `jev_retry_on_rate_limit`(기본 1회).
- 🔴 **그러나 무한정 기다리지 않는다.** `jev_retry_max_wait`(기본 15s)를 넘는 대기 요구는
  **기다리지 않고 포기**한다. 평가 배치는 *끝나야 하는 작업*이고, 서버가 "10분 뒤에
  오라"면 축을 null로 두고 **다음 배치가 이어받는 것**이 맞다.
- 🔴 **우리 일일 토큰 캡에서는 기다리지 않는다.** 캡은 예산이자 **키 유출 시 피해 상한**이고,
  자정까지 블로킹하면 야간 배치가 통째로 멎는다. 이 레포는 요청 경로 블로킹으로 스레드가
  고갈된 이력이 있다(SSE 고갈·블로킹 DNS). 캡 초과는 **호출 전에** 막고 축 null.
- **400 등 계약 오류는 재시도하지 않는다** — 다시 불러도 같은 답이 오고 비용만 쓴다.

## 3. 🔴 PHI 경계 — 문서 약속이 아니라 테스트가 경계다

의료·상담·STT·스크라이브는 **영구 제외**다. 판정에 원문이 필요한 과제라 비식별 피처만
보내는 설계가 성립하지 않는다(그 층은 로컬 구조화 출력으로 간다). 공급사 문서에는
**처리 리전도 HIPAA/GDPR 언급도 없다**.

3중으로 막는다:

1. **소스 스캔**(`tests/test_jev_phi_boundary.py`) — 의료·STT 계열 15파일에서 Jev 참조 0건.
2. **전 저장소 호출자 스캔** — `routes/`·`core/`·`scripts/`·`app.py` 전수에서 Jev를 참조하는
   파일이 허용 4개를 넘으면 실패. **허용 목록이 늘면 여기서 먼저 걸린다.**
3. **런타임 호출자 화이트리스트**(`_caller_allowed`) — 스캔은 동적 import를 못 보므로
   실행 시점에도 막는다. 평가 층만 허용.
4. **전송 페이로드 구조 고정** — 보내는 것은 `state`·`model`·`questions` **셋뿐**이어야 한다.
   나중에 누가 메타데이터를 얹으면 걸린다.

⚠️ 허용 목록에 **테스트 모듈을 일부러 넣지 않았다.** 넣으면 목록이 운영 사실과 달라지고
가드가 무엇을 막는지 회귀가 증명하지 못한다. 테스트는 가드를 직접 패치하고,
**가드 자체를 따로 검증**한다.
