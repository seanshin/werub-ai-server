## 1. 무엇이 갈렸었나 (실측 확진분)

`/api/chat` 스트리밍은 클라이언트에 raw를 흘리고 `finally:`에서 `force_korean(raw)`를
캐시·세션에 저장했다(v2.62.1). `force_korean`은 **한글 없는 줄을 통째로 삭제**하므로:

- 🔴 코드 답변: 라이브 571자(동작 코드 3종) → 캐시 재생 **167자**(코드 전삭제)
- 🔴 영어 답변(번역·영어 요청): 전량 삭제 → `full_text=""` → **캐시·세션 저장 자체가
  스킵**(hit=False·매번 재생성 + 세션 이력 소실)
- 🟡 ` ```sql ` 펜스 삭제(마크다운 구조 파괴) · 가나 문자 단위 소실
- 단 #8이 필터의 **의도된 효용**도 실증: 모델이 혼입한 한자·중국어(`살脔`·`细细切碎`)를
  정화해 재생이 라이브보다 깨끗했다.

## 2. 처치 — `core/korean.sanitize_stream_store()` (채택안 ③)

저장분 정화를 **문자 단위만**으로: 한자(`_CJK_CHARS`)·가나(`_JAPANESE`)·CJK 구두점
(`_CJK_PUNCT`) 스트립. **줄 삭제 없음** · 정화가 전부 비우면 **raw 반환**(저장 스킵 방지).
`routes/ollama.py` 스트림 finally가 `force_korean` 대신 이것을 쓴다.

- **클라이언트 계약 불변**: 라이브 스트림은 종전대로 raw(X6/v2.125.19에서 고정한 계약).
  바뀌는 것은 저장분의 필터 강도뿐.
- 기각한 대안: ①캐시에 raw 저장=혼입 문자 정화 효용 상실 · ②클라이언트에도 필터=
  코드·영어 사용례 파괴(raw 계약과 충돌).
- **유지한 트레이드오프(명시)**: 가나 제거는 `force_korean_token`과 같은 강도로 남긴다 —
  일본어 혼입이 이 레포의 실전 결함 클래스라 정화를 지키고, **요청된 일본어가 저장분에서
  지워지는 것**은 알려진 한계로 수용(#6). 키릴 등 비-CJK 외국 문자는 종전에도 못 지웠고
  이번에도 범위 밖.
- 부수 효과: 영어 답변이 이제 저장되므로 세션 `korean_ratio`에 0.0이 기록될 수 있다
  (정보성 필드·게이트 아님).
