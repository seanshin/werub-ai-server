## 2. 최악 문항(제21조) — 재현은 되는데 **표면이 매번 바뀐다**

`환자 진료기록 사본 발급 거부`는 22회 측정 중 8회 실패(36%)로 **유일하게 통계적으로
의미 있는** 반복 실패다. 근거를 고정하고 시드만 바꿔 재현했다.

```
실패 2/6 (33%)  ← 과거 36%와 동일. 개선 없음
친족·대리인 방향 반전 0/6  ← 오늘 배치에서 나온 그 표면은 재현되지 않음
대신: "만 14세 미만이면 형제·자매는 열람 요구 불가"(근거는 동의서 요건만 제외)
      "만 17세 미만은 주민등록증과 상관없이 제한 없음"(근거를 반대로)
```

🔑 **실패율은 그대로인데 표면이 회전한다.** 제21조는 대상(본인/친족/대리인) ×
서류요건 × 연령(14세·17세)이 다층으로 걸린 조문이고, 모델은 그 조건 결합을 33% 확률로
틀린다. **표면을 겨냥한 결정적 처치는 다음 표면에서 무력하다.**

이 클래스에 이미 두 처치가 들어갔고(규칙 4 — `v2.124.28`, 단서 부기 — `v2.124.73`)
둘 다 실패율을 못 낮췄다. **더 얹지 않는다.**

⚠️ 첫 재현 시도는 무효였다 — `/ask` 캐시를 피하려 `top_k`를 바꿨더니 **근거 자체가
달라져** 폐업·휴업 청크가 새로 들어왔다. 캐시 우회는 **생성을 직접 호출**해야 한다.

## 3. 🔴 벌칙 부기 — 만들었다가 **철회했다**

`detail.evidence_excerpt`로 대조해 *"근거에 없는 벌칙 수치를 쓴 답변 5/10"*을 얻었고,
그중 2건이 `faithfulness=1.000`이라 judge가 절반을 놓친다고 판단했다. 결정적 부기를
구현하고 회귀 15건까지 붙였다.

**그런데 근거를 잘못 잡고 있었다.**

```
detail.evidence_excerpt  = 4,000자 (잘린 발췌 — 4건 전부 정확히 4000자였다)
실제 /ask 근거            = 3,705 ~ 5,240자
```

실사용 근거로 다시 재니 **발동 0/40**. 지목했던 3건 전부 근거에 실재했다:

| | 답변 | 실제 근거 |
|---|---|---|
| 전자의무기록 | 500만원 | 제90조 원문에 있음 |
| 휴업·폐업 | 100만원 | 제92조③에 있음 |
| 리베이트 | 3천만원 | 제88조에 있음 |

> 🔑 **잔존 벌칙 결함은 창작이 아니라 오귀속이다.** 수치는 근거에서 가져오되 조문
> 귀속을 틀린다. 수치 대조로는 원리적으로 안 잡히고, 귀속 판정은 `v2.124.9/81`이
> 이미 그 한계에 서 있다.

발동 0회인 탐지기는 이득 없이 위양성 위험만 남긴다 — 실제로 개발 중 `id468`에서
답변 `300만원 이하 과태료` ↔ 근거 `300만원 이하**의** 과태료`의 **조사 하나** 차이로
제92조제1항을 정확히 인용한 답변(f=1.000)에 "확인되지 않음"을 붙였다.

**전량 revert.** 정규화를 고쳐 위양성은 없앴지만, 발동이 0이면 고칠 대상이 없다.
