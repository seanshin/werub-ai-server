# P6-1: 판정 확률 층 + Jev 외부 독립 판정자 — 기획서

**한 줄**: 우리 평가 층의 이분 판정에 **확률을 붙이고**(Phase 0 · 외부 의존 0),
그 위에 **상관이 낮은 제3 판정자**로 Jev를 배치 경로에 얹어(Phase 1) **사전 등록 기준으로
채택·기각한다**(Phase 2).

**왜 지금 이 기획인가**: 레포는 이미 교차검증의 **모델 이종성**을 명시적 설계 목표로 적어
두었다 — *"judge와 같아지면 교차검증이 자기 자신을 확인하는 셈"*(`model_routing.json:55`).
그런데 현재 그 이종성을 **같은 계열(qwen2.5)의 다른 크기(14b vs 7b)**로 사고 있다. 같은
가족은 같은 편향을 상당 부분 공유하므로, **이 목표는 절반만 달성된 상태**다. Jev는 구조·
벤더가 모두 다른 판정자라 이 공백에 정확히 들어맞는다 — 그리고 **그것이 로컬로 살 수 없는
유일한 항목**이다(확률 자체는 Phase 0가 공짜로 만든다).

> 📌 이 문서는 **착수 가능한 형태**로 쓴 기획서다. 조사·근거는 조사 정본에,
> 측정 결과는 착수 후 §12 진행 로그에 남긴다. **기획서에 적혀 있음은 이행 이유이지
> 효과의 증거가 아니다**(v2.125.25 교훈) — 모든 채택은 §8 판정을 통과해야 한다.

## 1. 목표 · 비목표

### Goals

- **G1 (Phase 0)** 충실도 평가의 주장별 entailment에 **confidence(확률)** 축 신설. 외부 의존 0.
- **G2 (Phase 1)** Jev를 **제3 독립 판정자**로 배선. 배치 경로 · PHI 0 · fail-open.
- **G3 (Phase 2)** 같은 문항에 `judge · MiniCheck · 로컬확률 · Jev` 4축을 나란히 놓고 **§8 기준으로 판정**.
- **G4** PHI 경계를 **코드가 보증**한다(회귀 동결 — 문서 약속이 아니라 테스트).

### Non-Goals (하지 않는다 · §9에서 재확인)

- 요청 경로(의료 · 상담 · STT · 스크라이브)에 Jev 투입 — **영구 제외**
- Jev `Score`를 절대 점수로 사용 — 공급사가 *"weak in numerical calibration"* 명시
- eval 5축 점수(G-Eval) 대체 — 이 기획의 대상이 아니다
- Jev 생성 용도 — 모델이 생성 학습되지 않았다

# Phase 0 — 로컬 판정 확률 축 (외부 의존 0 · 즉시 착수 가능)

## 4. 설계

### 4-1. 확률 추출 규약 (신규 `core/decision_prob.py`)

```python
def extract_label_prob(logprobs: list, labels: dict[str, list[str]],
                       *, at: int | None = None) -> dict[str, float] | None:
    """판정 토큰 위치의 top_logprobs → 라벨별 확률(재정규화).

    labels: {"true": ["true","True"], "false": ["false","False"]}
    반환:  {"true": 0.03, "false": 0.97}  |  None(라벨 미검출)

    규율:
      - **`top_logprobs` 목록을 읽는다.** 선택 토큰 자신의 `logprob`은 제약 하에서
        신뢰할 수 없다(F2·F3 실측 — `"C`는 무제약 top에 없다).
      - 라벨 변종은 **strip + casefold 후 합산**한다(F5 — 안 하면 과소평가).
      - 라벨이 하나도 안 잡히면 **None**. 0.5로 채우지 않는다(원칙 #1·#7).
      - 합이 0이면 None. 재정규화는 잡힌 라벨들 안에서만 한다.
    """
```

- **단일 토큰 라벨 규약**(F2·F3): 판정용 스키마의 값은 **단일 토큰으로 분해되는 라벨**만
  쓴다(`true/false`, `A/B/C`, `1/2/3`). 한국어 다중 토큰 값(`"상보파싱"`)은 **금지** —
  답과 확률을 동시에 망친다. 라벨 뜻은 **시스템 프롬프트에 적는다**.

### 4-2. 라우터 — `logprobs` 통과 (`core/model_router.py`)

`Result.raw`가 원본 JSON을 이미 싣으므로(F6) **응답 측 변경은 없다.** 요청 측만:

| 위치 | 변경 |
|---|---|
| `OllamaAdapter._payload` | `logprobs: bool=False`, `top_logprobs: int|None` 인자 추가 → `True`일 때만 페이로드에 싣는다(**기본 미부착 = 기존 페이로드 완전 동일**) |
| `OllamaAdapter.generate` | 인자 통과 |
| 모듈 함수 `generate()` | 인자 통과 |
| `stream()` · `chat()` | **손대지 않는다** — 평가 경로는 비스트림이다(범위 최소화) |

> 🔑 **기본값 False가 계약이다.** 부착 조건부이므로 기존 59 task의 페이로드는 바이트 단위로
> 동일하다 — 동일성 회귀(v2.125.13 자산)가 그대로 통과해야 한다.

### 4-3. 충실도 배선 (`core/faithfulness.py`)

- `_route()`는 `r.text`만 반환하므로 **`_route_full()` 신설**(동일한 실패 규율 =
  `not r.ok`면 `RuntimeError`. **평가 경로는 강등하지 않는다** — 기존 docstring 규율 유지).
  `_route()`는 `_route_full()`의 얇은 래퍼로 바꾼다(기존 호출자 무변경).
- `_qwen_entail_check()` → `(bool, prob | None)` 반환으로 확장.
  - 호출에 `logprobs=True, top_logprobs=5`
  - `extract_label_prob(r.raw.get("logprobs"), {"true":["true","True"],"false":["false","False"]})`
  - `prob = p["true"]` (supported 확률). 미검출 → `None`
### 4-3a. 호출자 전수 (확인 완료 — 설계 확정)

| 지점 | 형태 | 처리 |
|---|---|---|
| `minicheck_verify:366` `check = checker or _default_checker()` | **유일한 프로덕션 소비 지점** | 확률 경로를 여기서 분기 |
| `_default_checker:359` | 백엔드 선택(`qwen-entail` 기본) | 불변 |
| `tests/` 4건 (`test_faithfulness` 3 · `test_judge_router_migration` 1) | `is True` / `is False` 단언 | **반환 형태를 바꾸면 깨진다** |

⇒ **파괴 없는 설계로 확정한다**:

- `_qwen_entail_check()` — **반환 `bool` 그대로 유지**(기존 계약·테스트 4건 무파손)
- `_qwen_entail_check_ex()` **신설** → `(bool, prob | None)`
- `_qwen_entail_check()`는 `_ex()[0]`을 돌려주는 얇은 래퍼가 된다
- `minicheck_verify(..., want_prob=False)` 인자 추가 — `True`일 때만 `_ex` 경로를 쓰고
  `(verdicts, probs)`를 반환. **기본값에서는 반환 형태·동작이 완전히 동일**하다

**확률의 청크 집계 규약**(max-over-chunks 프로토콜과 정합):
- `verdict=True`: **지지로 판정한 그 청크**의 `P(supported)` (루프가 break한 지점)
- `verdict=False`: 전 청크 중 **`P(supported)`의 최댓값** — 가장 아슬아슬했던 값.
  🔑 이게 이 축의 실사용 값이다(*judge가 확신한 부정* vs *간신히 부정*을 가른다)
- `verdict=None`(판독 불능): `None`
- 청크별 확률 미검출은 **그 청크만 건너뛴다**(판정 자체는 기존대로)

### 4-4. 저장 · 노출

- `eval.db` **스키마 변경 없음** — 기존 `detail` JSON에 `entail_prob` 추가(문항별 배열).
- `/api/eval/status`: `faithfulness.confidence` 집계(평균 · 하위 구간 건수) + `questions[].entail_prob[]`.
- `/eval-monitor`: KPI 타일 1개 + **확률 하위 구간 드릴다운**(이게 이 축의 실사용 값이다).
- **미측정은 `null`**(구 배치 · logprobs 미지원 응답 · 라벨 미검출) — "0건"과 가른다.
