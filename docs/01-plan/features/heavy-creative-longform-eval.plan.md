# 사전 등록 — heavy tier 창작·장문 축 측정 (G1)

작성 2026-08-25(측정 **전**) · 기획 `remaining-work-2026-08-19.plan.md` §3-G1 · 실행은 GPU 유휴 시간(⚠️평가 배치·게이트와 비동시)

## 0. 왜 사전 등록인가

- heavy(qwen3.6:35b-a3b)는 **grounded 독해에서 상주 14b와 완전 무승부**였다(v2.125.5 N=40 재측정:
  충실도 3승3패 동률34 p=1.000 · 품질 15승15패 동률9 p=1.000 · 지연 5.52배). "창작·장문에서는
  값을 하는가"는 **미측정**이라 heavy를 권하지도 말리지도 못하는 상태다.
- 선례 함정: N=8 우세→N=16 재현 실패(EXAONE·v2.124.78) · N=16 유의(p=0.039)→**N=40에서 소멸**
  (v2.125.5). ⇒ **N=40 미만으로 판정하지 않는다.**
- 한 번 잰 값 위에 기준을 만들지 않는다(v2.125.2) — 기준·임계·무효 조건을 여기 먼저 적는다.

## 1. 팔·표본

| | A(대조) | B(후보) |
|---|---|---|
| 모델 | 상주 `qwen2.5:14b` | heavy `qwen3.6:35b-a3b` · `think=false` |
| 경로 | 동일 하네스에서 직접 생성(프로덕션 경유 아님 — 캐시·큐 간섭 배제) · **options 양팔 동일 명시**(repeat_penalty 1.1 포함 — D2 핀과 동일 값) |

표본 **N=40 고정**(사전 확정 후 변경 금지):
- **창작 24**: story/novel 실경로 프롬프트 분포에서 발췌·재구성 — 단편 생성 8(장르 지정) ·
  이어쓰기 8(앞부분 300자 제공) · 문체 변환/개작 8. 길이 지시 포함(400~800자).
- **장문 추론·구성 16**: 장문 요약 6(2,000자+ 원문) · 구조화 글쓰기 6(개요→본문) · 다단계 지시 4.
- 표본 파일: `docs/01-plan/references/heavy-creative-eval-questions.json`(실행 전 커밋 = 등록).

## 2. 측정 축 (양팔 동일 도구)

1. **품질 judge** — `core/llm_judge`(judge=상주 14b·양팔 같은 judge) 5차원. ⚠️판정은 평균이 아니라
   **쌍별 승/패/동률 부호검정**(평균은 동률 많을 때 소수 문항 크기에 끌린다 — v2.125.5 교훈).
2. **결정적 한국어 축** — `korean_humanize`: 반복 점수 · 한국어 비율 · risk_band. judge와 독립 계열.
3. **지시 준수(결정적)** — 길이 지시 충족률 · 요구 요소 포함(질문별 필수 신호 사전 등록).
4. **지연** — 관측만(판정축 아님). 품질 우위가 없으면 잴 이유도 없다(v2.125.5 규율).

## 3. 채택/기각 기준 (측정 전 고정)

- **heavy 권고(창작·장문 한정)** = ①품질 부호검정 p<0.05로 B 우위 **그리고** ②결정적 축(반복·
  한국어 비율·지시 준수)에서 B 비열세(어느 축도 유의 열세 없음) **그리고** ③빈 응답·붕괴 0.
- 그 외 전부 = **현상 유지**(heavy는 on-demand 그대로·"품질이 더 좋다"를 전제로 배선하지 않는다).
- 부분 우위(특정 유형만 우위)는 **관찰 기록**으로만 남기고 별도 사전 등록 없이 권고로 승격하지 않는다.

## 4. 무효 조건 (하나라도 걸리면 그 실행은 판정에 못 쓴다)

- B의 `thinking` 누출(사고 문자 수 >0) — v2.125.5에서 후보가 `think:false`를 무시해 1차 측정이
  통째로 무효된 선례. **본 측정 전 capability 검증 3문항**(사고 0자·본문 정상)을 먼저 통과할 것.
- 캐시 히트 의심(0.00N초 응답) · 재채점 전용 모드(`--reuse-answers`)와 배치 추세 혼용(+0.075 이동 선례).
- 측정 중 다른 GPU 작업 겹침(38분 정지 선례) — 시작 전 `/api/ps`·큐 확인.
- **노이즈 바닥 미측정** — 본 측정 전 A팔 동일 표본 2회 실행으로 judge 흔들림 밴드를 먼저 잰다.
  A-A 차이가 A-B 차이와 같은 급이면 그 축은 판정 불가로 선언한다.

## 5. 실행 절차

1. 표본 40문항 작성·커밋(=등록 확정) → 2. B capability 검증 3문항 → 3. A-A 노이즈 바닥 →
4. A/B 본 실행(교차 순서·seed 고정) → 5. 판정(§3 기준 그대로) → 6. 릴리즈 문서에 결과·원자료.
- 예상 소요: B 생성이 문항당 30~90s(35b·창작 장문)면 본 실행만 1.5~2.5h — GPU 유휴 창 필요.
- 원자료: `docs/01-plan/references/heavy-creative-eval-result.json`.

## 6. 하지 않을 것

- N<40 판정 · 평균 비교로 우위 선언 · 지연을 품질과 섞어 종합점수화 · 표본 사후 교체 ·
  "이왕 잰 김에" 축 추가(축 추가는 재등록).
