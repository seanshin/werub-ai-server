# v2.125.2 — 게이트가 캐시를 읽고 있었다 · 자기 부하 처치는 A/B로 기각

2026-08-12

v2.125.1이 "게이트가 자기 부하로 흔들리기 시작했다"를 **관찰 대상**으로 남겼다. 그걸 재러 갔고,
**채택 하나·기각 하나**로 끝났다. 기각한 쪽에서 배운 것이 더 크다.

## 1. 게이트 자기 부하 실측 — 무엇이 시간을 쓰는가

스모크 전 구간(173체크)에 **체크별 타임스탬프 × `ollama /api/ps` 1초 폴링**을 붙여 한 번 돌렸다.

| | 값 |
|---|---|
| 전체 | 406.4초 · 173/173 통과 |
| 모델 적재 | **37회**(방출 37회) · 모델 6종 |
| 동시 적재 수 | 표본 404개 중 **0개=157(39%) · 1개=247 · 2개 이상 0** |
| 체크 대기 | 406.3초 중 **적재 구간과 겹친 것 399.3초(98%)** |

🔑 **구속조건은 슬롯이 아니라 VRAM이다.** 15.9GiB에서 상주 `qwen2.5:14b`가 10.4GB를 쥐면
`mindwell`(~10.5) · `qwen3:8b`(~6.3) · `qwen2.5:7b`(~5.8) · `coder:14b`(~10) **어느 것도 못 들어온다**.
실측 동시 적재가 끝까지 1이었던 이유이고, `OLLAMA_MAX_LOADED_MODELS`(=3)를 올려도 안 바뀐다.

적재 시퀀스가 왕복을 그대로 보여 준다 — 상담 **1건 안에서**:

```
1s-14b  4s+mindwell 5s-mindwell 12s+14b 13s-14b 15s+qwen3:8b …
                                └ 7초 걸려 적재됐다가 1초 만에 쫓겨난다
```

원인은 스위트 순서가 아니라 **주기 예열**이었다. 큐 워커 루프가 대기 잡이 없을 때(=평상시)
**2초마다** `_ensure_default_model()`을 부르는데, 이 함수는 "상주 모델이 안 보이면 끌어온다"만
판단하고 **다른 모델이 방금 쓰였는지는 보지 않는다**.

⇒ 처음 세웠던 처치 후보(스위트를 모델별로 묶어 재배치)는 **측정이 겨냥을 부정해 철회**했다.
왕복은 스위트 *사이*가 아니라 스위트 *안에서* 일어나고 있었다.

## 2. 🔴 채택 — 게이트가 캐시를 읽고 있었다

같은 측정에서 나왔다. `medlaw` · `control` · `predict` · `adverse-drug` **43체크가
0.001~0.015초**로 지나갔다. 결정적 판별:

| 요청 | 소요 |
|---|---:|
| 통제군 질문 그대로 | **0.0019초** |
| 같은 질문에서 **한 글자만** 변경 | **4.29초** |
| `adverse-drug` 동일 페이로드 | **0.015초** |
| 나이만 70→**71** | **6.45초** |

경위도 확정했다 — 워커 13:12 기동 → 배포 스모크가 캐시를 채움 → 10분 뒤 단독 실행이 그걸 읽음.

⚠️ **배포 경로 자체는 정상이다.** `deploy.sh`가 4단계에서 HUP를 걸어 워커가 새로 뜨므로
스모크 시점의 인메모리 캐시는 비어 있다. 문제는 `deploy.sh` 주석이 적어 둔 **그 절차**다:

> *"흔들리나 보려고 **단독 재실행**한다"*

그 순간 저 43체크는 지난 답을 다시 볼 뿐이다. **흔들림을 판정하려고 돌린 실행이 흔들림을 못 본다.**
스위트 첫 줄에 "실제 모델을 호출해 쓸 만한 답이 나오는가를 본다"고 적어 놓고 그러고 있었다.

### 처치 — `X-No-Cache: 1`(로컬 직결 요청 한정)

- `core.cache.bypass_allowed` **순수 판정**. 프록시 헤더(`X-Forwarded-For`·`X-Real-IP`·
  `CF-Connecting-IP`)가 하나라도 있으면 로컬로 보지 않는다 — v2.109.2 H1과 같은 규율이다
  (nginx·CF를 지나온 요청은 `remote_addr`이 127.0.0.1로 보일 수 있고, 그걸 로컬로 인정하면
  외부가 헤더를 붙여 보낸다).
- 🔑 **판정을 캐시 객체에 넣었다**(`routes/cache_ctx.RequestAwareTTLCache`).
  읽기/쓰기 지점이 20곳이 넘고 `korean` 하나에만 여러 쌍이라, 호출 지점마다 조건을 넣으면
  새 지점에서 빠뜨린다. 그리고 **빠뜨린 사실은 "빠르게 통과했다"로만 보여 조용하다.**
- ⚠️ **읽기만 건너뛰고 쓰기는 둔다.** 쓰기까지 막으면 우회 실행이 낡은 값을 남겨
  바로 다음 호출이 우회 이전 답을 다시 본다.
- 배선 5곳: `medical_law` · `medical` · `writing` · `coding` · `korean`. 헤더가 없으면 기존 동작 100%.

📌 `/api/chat` 캐시는 뺐다 — app.py의 **별도 캐시 클래스**이고, 그쪽 스모크 체크는 모델 행동이
아니라 **큐 대기 헤더**를 보므로 캐시 히트가 판정을 가리지 않는다.

**대가는 정직하게**: 게이트가 느려진다. 그게 이 처치의 값이다 — 43체크가 처음으로 반드시
실제 생성을 탄다(배포 중 실측: `predict` 스위트 0.0초 → **12.9초**).

## 3. 🔴 기각 — 상주 예열 양보 (통제 A/B)

§1의 왕복을 없애려고 **"비-상주 모델을 방금 썼으면 상주를 즉시 되찾지 않는다"**를 구현해
배포했다(게이트 173/173 통과). 그리고 **통제 A/B에서 기각했다.**

`--only counseling` · backoff `0 → 30 → 0 → 30` 연속:

| arm | backoff | 소요 | 적재 |
|---|---:|---:|---:|
| A1 | 0 (기존) | 93.8s | 10회 |
| B1 | 30 (변경) | 107.8s | 14회 |
| A2 | 0 (기존) | 116.4s | 14회 |
| B2 | 30 (변경) | 107.5s | 11회 |

- **노이즈 바닥(A1−A2) 22.7초** · **변경 몫 +2.6초** ⇒ **판정 불가**
- 케이스 짝지음(6쌍): A 우세 3 · B 우세 1 · 동률 2 = 신호 없음
- 🔴 결정타: **적재 횟수가 줄지도 않았다.** 줄이려고 만든 처치가 **설계한 일 자체를 안 했다.**

**값만 0으로 두는 선택은 하지 않았다** — 아무도 타지 않는 분기가 남고, 그게 정확히
"효과 미확인 처치를 말이 되니까 남기는" 것이다(v2.124.63). 코드는 되돌렸고 발견은 여기 남긴다.

### 남기는 사실(재현된 측정)

- 16GB에서 상주 14b와 도메인 모델은 **공존하지 못한다**(동시 적재 실측 최대 1)
- 상담 1건 안에서 14b가 7초 걸려 적재됐다 1초 만에 쫓겨나는 구간이 **실재한다**
- 다만 그 왕복을 없애도 **벽시계 시간은 안 줄었다**

## 4. 📌 방법론 — 노이즈 바닥은 측정 *전에* 잡는다

이 릴리즈의 진짜 수확이다.

| | counseling 스위트 |
|---|---:|
| 기준선(단독·13:28) | **248.5초** |
| A1 (같은 설정) | **93.8초** |
| A2 (같은 설정) | **116.4초** |

**같은 설정인데 2.6배가 흔들린다.** 나는 아침에 **한 번 잰 406초**를 "counseling이 게이트의 61%"로
읽고 그 위에 처치를 설계했다. 그 61%가 이 변동 폭 안이었다.

같은 실수의 다른 얼굴도 있었다. 배포 스모크에서 counseling 두 케이스가 20.5→78초·18.3→62초로
나오자 나는 **"내 변경이 악화시켰다"**고 보고했고, 곧이어 **"채팅 지연이 물린다"**는 추론까지 얹었다.
전자는 조건이 다른 비교(단독·웜 vs 배포·콜드)였고, 후자는 이력 데이터가 오히려 반대였다
(구 코드 스모크 구간 p95 **5,320ms** ↔ 신 코드 **3,882ms**). **둘 다 근거 없이 앞서간 것이다.**

## 5. 🐞 부수 — 서로게이트를 설명하는 독스트링이 서로게이트를 만들고 있었다

`core/cache.py`의 `encode_for_hash` 독스트링은 **짝 잃은 서로게이트 때문에 `/api/chat`이
1,726건 터진 사건**을 설명한다. 그런데 그 설명문이 `` `\ud83c` ``를 **일반 문자열 안에** 적어
파이썬이 이스케이프로 해석했다 — 즉 **그 결함을 설명하면서 그 문자를 실제로 만들어 냈다.**

파이썬 3.14에서 `import core.cache`가 `UnicodeEncodeError`로 실패한다(구버전은 통과하므로
GPU 라이브에는 영향 없음). 이스케이프 처리로 교정.
