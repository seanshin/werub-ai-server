# v2.125.63 — Settings 미저장 변경 경고 + 🔴패널 중첩 결함·이미지 '무제한' 표시 결함 봉합

기준 v2.125.62 · 기획 `docs/01-plan/features/admin-menu-settings-cleanup.plan.md` §4.1 잔여(09-29 이월)

## 1. 미저장 변경 경고 (계획 잔여)

**'저장됨'의 기준을 먼저 정했다** — 절마다 저장 방식이 달라(저장 버튼·즉시 동작 버튼·읽기 전용) 이월된 항목이다.

- 기준 = **그 입력칸을 마지막으로 채운 서버 값**. 로더가 값을 채운 직후와 저장 **성공** 직후에 기록한다
  (저장 실패는 기준을 안 바꾸므로 계속 미저장으로 남는다 — D4 `saveJSON`과 같은 판정).
- 추적: 인증 2 · 큐 기본 모델 · 모델 초기화 7 · Ollama 성능(쓰기 가능 환경만 — GPU는 읽기 전용이라 제외) · 이미지 보관 3.
  webhook 3종은 시크릿이라 서버 값이 화면에 없으므로(D2) **칸에 뭔가 쓰였으면 미저장**.
- 추적 안 함: 비밀번호 칸(설정이 아니라 1회 동작·자동완성이 가짜 경고를 만든다) · API 키 이름 · 상주 모델 선택(버튼이 곧 동작) · 읽기 전용 절.
- 묻는 곳: 절 전환 · Settings에서 다른 탭으로 · hash 이동(뒤로 가기) · 새로고침/창 닫기(`beforeunload`).
  "버리고 이동"은 입력칸을 기준값으로 **되돌린다**(안 그러면 숨은 절의 편집이 다음 진입 때 또 경고된다).
  취소하면 hash를 현재 절로 복원한다. **같은 절을 다시 누르면** 로더가 편집을 덮어쓰던 것을 막는다(아무것도 안 함).

## 2. 🔴 패널 중첩 결함 (v2.125.59~62, 작업 중 발견)

v2.125.59가 '접속 정보' 카드를 고치며 `</div>` 하나를 남겼다. 절 안의 여분 닫힘은 브라우저가 무시하지 않고
**바깥 `settings-body`를 닫는다** →
- '시스템 정보' 절이 소메뉴 옆 **셋째 칸**으로 밀려남.
- 패널 끝의 닫힘이 하나씩 밀려 **`.container`까지 닫힘** → 뒤의 패널 6개(Knowledge·Image·Activity·Users·Training·Logs)가
  폭 제한(1100px)·가운데 정렬·여백 없이 렌더.

콘솔 오류 0·기능 정상이라 브라우저 확인에서도 지나갔다(클래스 #1과 같은 무성). 회귀 `test_panels_and_settings_sections_nest_correctly`
(브라우저식 중첩 시뮬레이션 — 구 템플릿에서 실패 확인).

## 3. 🔴 이미지 보관 '무제한'(0)이 7일·500개·2GB로 보이던 결함 (잠재)

`loadImageStorage`가 `cfg.image_retention_days || 7` — 0(무제한, `_cleanup_images`가 >0일 때만 정리)을 기본값으로 바꿔 보여 줬다.
무제한으로 저장한 뒤 그 화면에서 다시 저장하면 **한도가 되살아나 일일 정리가 이미지를 지운다**. `??`로 교정.
라이브 값은 30·5000·10000이라 **무증상**이었다.
