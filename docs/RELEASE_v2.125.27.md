# v2.125.27 — medlaw dedup이 **최신 개정분을 지우고 있었다**: 그룹핑 재설계 + 삭제 opt-in

날짜: 2026-08-31 | 발견: v2.125.26 상태 점검에서 백로그에 없던 채 80일째 CRITICAL을 내던 항목을 착수

## 1. 착수 배경과 🔑 전제의 붕괴

`core/medlaw_processor.py:dedup_versions`의 대량 삭제 가드가 **2026-06-12부터 17회 SKIP**하며
삭제 대상이 2790→**3017청크**로 늘어 있었고, CRITICAL 로그는 *"워치독 동반 수동 dedup 요망"*
이라 **삭제를 권하고** 있었다. 계획은 "구버전이 검색을 오염시키는지 재고, 확인되면 수동 dedup"이었다.

**규율대로 탐지기를 먼저 라벨 통제군에 걸었더니 전제가 무너졌다.** 이건 구버전 중복이 아니다.

`_base_key`가 파일명에서 `전문|일부개정|개정|제정`과 고시번호·차수를 **전부 지운 뒤** 묶는다.
그래서 성격이 다른 문서가 한 그룹이 된다. 실코퍼스 16그룹 전수 판독:

```
[3] 의료급여수가의 기준 및 일반기준
    KEEP   378청크 [전문]     2025-171호 전문
    DELETE  38청크 [일부개정] 2026-138호 일부개정      ← 최신 개정분
[6] 건강보험 행위 급여·비급여 목록표
    KEEP   108청크 [무표기]   2024-280호
    DELETE  8건 전부 [일부개정] 2025-182·201호, 2026-1·39·55·88·125·153·173호
```

**전문(통합본)과 일부개정(개정 diff)은 중복이 아니라 상보 관계**이고, 일부개정은 회차마다
내용이 다른 별개 문서다. 거기에 정렬 1순위가 **청크 수**라 "가장 긴 것(대개 구버전 전문)"이
살아남는다 ⇒ **16그룹 중 9그룹에서 보존 대상이 최신본과 불일치**했다.

## 2. 검색 영향 측정 — 공허하지 않다 (N=10 질의 · top-5 · 읽기 전용)

삭제 계획 파일이 **근거의 32%(16/50)**를 차지했다. 문제는 그 내용이다:

```
q: 선별급여 지정 및 실시 기준
   ok    2025-145호 일부개정      ← 보존 대상(구본)
   STALE 2026-102호 일부개정      ← 삭제 대상(최신)
   STALE 2026-122호 일부개정      ← 삭제 대상(최신)
   STALE 2026-154호 일부개정      ← 삭제 대상(최신)
```

실행했다면 **2026년 개정분이 검색에서 사라지고 2025년 판이 남는다.** 의료법 자문에서 오답 생산이다.
⇒ **가드가 80일간 코퍼스를 지켜온 것**이고, 로그의 권고를 따랐으면 최신 개정분이 사라졌다.

진짜 구버전도 있다 — `신의료기술 평가결과 고시 전문` 3판(3,477청크 = 컬렉션의 26%),
`평가 유예 고시 전문` 5판, `혁신의료기기 지정 현황` 4판. 실제로 `평가 유예` 질의 top-5에
25년7차 구버전 전문이 올랐다. **정책 결정(2026-08-31): 구버전 전문은 보존한다**
(과거 시점 기준을 묻는 질의 대비) ⇒ 삭제 후보는 "같은 문서가 두 번 색인된 것"뿐이다.

## 3. 처치

- **`_doc_identity` 신설** — `_base_key`와 **정반대 방향**이다. 지우는 것은 색인 부수 정보뿐
  (titleId 접두사·확장자·구분기호). 성격 마커·고시번호·차수·날짜는 **남긴다**. 다르면 다른 문서다.
- **삭제 후보 = 두 조건 동시 충족**: ① `_doc_identity` 일치 ② **청크 수까지 일치**.
  청크 수가 다르면 `ambiguous`로 빼둔다(hwpx/pdf 파싱 차이 15 vs 11청크, 동명 초안 9 vs 3청크가 여기 걸린다).
- **보존 = 최신 titleId**(청크 수가 아니다).
- **`apply=False`가 기본** — 증분 스케줄러(`core/medlaw_processor.py:270`)는 인자 없이 부르므로
  **라이브에서 자동 삭제가 일어나지 않는다**. 삭제는 운영자가 워치독을 켜고
  `scripts/dedup_medlaw.py --apply`로 명시 실행한다.
- `_base_key`는 호환용으로 남기되 **그룹핑에서 제거**하고, docstring에 왜 쓰면 안 되는지 실측을 남겼다.
- CRITICAL 메시지에서 "수동 dedup 요망"(=파괴적 행위 권유)을 걷어내고 "계획을 먼저 검토"로 바꿨다.

### 재설계 후 실코퍼스 dry-run

| | 종전 | 재설계 후 |
|---|---|---|
| 삭제 계획 | **3,017청크 / 40파일** | **139청크 / 4파일** |
| 계획에 든 최신 개정분 | 약 197청크 | **0** |
| 계획에 든 구버전 전문 | 약 2,669청크 | **0**(정책상 보존) |
| 판단 보류(`ambiguous`) | — | 4파일 |
| 실제 삭제 | (가드가 차단) | **0**(dry-run 기본) |

계획에 남은 4건은 전부 **동일 파일명 + 동일 청크 수**다(별표1 변경사항 표기 119·의료기기법
시행령 입법예고문 제2026-132호 9·의료평가통합정보시스템 고시 제정 8·선별급여 제2026-154호 3).

## 4. 검증

- 신규 회귀 20건 `tests/test_medlaw_dedup_identity.py` — **라이브 코퍼스에서 실제로 관측된
  파일명을 라벨 통제군으로** 썼다:
  - 양성 통제(묶이면 안 되는 것) 8쌍 — 전문 vs 일부개정 · 고시번호가 다른 개정 · 차수가 다른 전문 ·
    날짜가 다른 현황 스냅샷. 🔴 이게 깨지면 최신 개정분이 삭제 계획에 든다.
  - **음성 통제**(묶여야 하는 것) 4쌍 — 너무 좁혀서 진짜 중복을 못 잡는 것도 결함이다.
  - 동작: dry-run이 기본 · 보존은 최신 titleId(더 긴 쪽이 아니다) · 청크 수 상이는 HOLD ·
    고시번호가 다른 개정 3건 전원 생존 · 전문+일부개정 비병합 · 가드 유지 · 스크립트 `--apply` 필수.
- `tests/test_medlaw_delete_guard.py` 픽스처 갱신 — 종전 픽스처(10 vs 8청크)가 **"더 긴 쪽 보존"이라는
  결함 자체를 계약으로 고정**하고 있었다. 진짜 중복(8 vs 8)으로 교체.
- `tests/test_medlaw.py::test_base_key_groups_versions`는 동작을 그대로 두되 **폐기 사유를 명시**
  (이 함수를 다시 그룹핑에 쓰면 안 되는 이유가 그 동작 자체다).
- 전체 회귀 **1995 passed · 9 skipped · 1 xpassed**, 실패 1건은 `test_korean_spellcheck` Ollama
  read timeout으로 **medlaw 무관 flake**(단독 재실행 15/15 통과 — 측정 스크립트가 임베딩으로
  Ollama를 점유한 탓). 실질 1996.

## 5. 남긴 것 · 드러난 것

- 🟡 **재색인 churn 가능성(코드로 확인·실증은 안 함)**: `medlaw_incremental`의 `known` 집합은
  별도 레지스트리가 아니라 **컬렉션 내용에서 파생**된다(`core/medlaw_processor.py:294`).
  따라서 dedup이 지운 파일이 크롤 창 안에 있으면 **다시 내려받아 재색인**되고, 다음 dedup이 또
  지운다 — `col.delete` 반복은 `link_lists.bin` 137G 디스크풀 인시던트의 기전과 같은 모양이다.
  dry-run 기본이 이 경로도 함께 닫는다.
- ⚠️ **2026-06-11에 dedup이 한 번 실행됐다**(`25개 구버전 제거(2922청크)` — 가드는 그 다음 날 도입).
  그때는 결함 있는 로직이었으므로 최신 개정분이 삭제됐을 수 있다. 다만 `known`이 컬렉션 파생이라
  크롤 창 안이면 재색인됐을 것이다. **원자료가 없어 사후 판정은 불가**하고, 사실만 기록한다.
- **139청크 실제 삭제는 하지 않았다** — 세션 결정이 "그룹핑 교정 + 회귀만, 삭제 실행 없음"이었다.
  실행할 때는 워치독(`_link_lists_warn`) 동반 + `--apply`.
- `ambiguous` 4건(동명·청크수 상이)은 사람이 원문을 봐야 판정된다 — 자동 처리 대상이 아니다.
