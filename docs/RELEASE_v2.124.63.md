# Release v2.124.63 — 용어 힌트가 전사를 파괴하던 결함 봉합 (토큰 기준 캡)

날짜: 2026-07-30 | 종류: fix(stt) | 배포: GPU graceful HUP(NRestarts 0)

## 🔴 배경 — 내가 v2.124.42에 넣은 기능이 전사를 망가뜨리고 있었다

edu 실측 제보(181초 음원·같은 서버 설정, **힌트 개수만** 변경):

| 힌트 | 결과 |
|------|------|
| 없음 | 단어 311 · 세그먼트 41 · 목표용어 6/7 ✅ |
| 24개 | 세그먼트 28(이미 변형) |
| **30개(168자)** | **단어 94(−70%)** · 세그먼트 13 — `status: completed`인데 내용이 사라짐 |
| **38개(207자)** | `The maximum decoding length must be > 0` **실패** |

edu는 **`options.vocabulary` 전송을 중단**했다(운영 배포). 더 나쁜 쪽은 실패가 아니라
**조용한 붕괴**다 — 상태가 `completed`라 호출자가 탐지할 수 없고, 그대로 자막이 되면
학습자가 잘린 내용을 본다.

## 원인 — 캡의 단위가 틀렸다

whisper 디코더는 `max_length=448`이고 그중 **절반(224토큰)만 프롬프트**(initial_prompt +
hotwords + 직전 문맥)에 쓸 수 있다. 그런데 캡이 **600자**(`MAX_INITIAL_PROMPT_CHARS`)였다.
한국어는 대략 **1.2토큰/자**라 600자면 **약 720토큰** — 창의 3배다.

코드 주석에는 "whisper 프롬프트 창(224토큰) 때문에 shortlist 전제"라고 **정확히 적어 놓고
캡은 문자수로 걸었다.** 아는 것과 강제하는 것이 어긋난 전형적인 사례다.

## 수정 — `core/stt_hints.py` (신설·단일 소스)

- `estimate_tokens()` — 한글 1.2/자 · 그 외 0.32/자(과소추정 회피 방향).
- `cap_hints()` — **토큰 기준 96** 상한(창 224의 절반 이하 = 디코딩 자리를 남긴다).
  **항목(쉼표) 경계에서만 자른다** — 항목 중간을 자르면 존재하지 않는 토막을 바이어스해
  오히려 오인식을 만든다. 첫 항목 하나가 상한을 넘으면 통째로 버리지 않고 그것만 쓴다.
- `hint_report()` — **잘린 개수를 호출자에게 반환**(무성 절단 금지 규율).

적용: 배치 STT(`meeting_pipeline.stt_options` → 응답 `result.hints`) · 실시간
STT(`stt_realtime._normalize_terms`·상태에 `vocab_max_tokens` 노출). **같은 whisper 제약이므로
두 경로 모두 같은 캡**을 쓴다 — 실시간 쪽도 600자 캡이라 잠재적으로 같은 결함이었다.

## 부수 — 테스트가 배포 전에 잡은 것

`_VOCAB_MAX_CHARS`를 제거하면서 다른 두 곳(등록 응답·`/status`)의 참조를 놓쳤다.
회귀가 `NameError`로 잡았다 — 이번 세션에서 반복된 "휴면 코드 NameError" 클래스가
**라이브 전에** 걸린 첫 사례다.
