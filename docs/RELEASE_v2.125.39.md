# v2.125.39 — 세션 만료 탭의 401 폴링 폭주 백오프 (라이브 로그 판독 발견)

2026-09-03 · 회귀 신규 4

## 발견 — 코드 큐 소진 후 라이브 판독 관례가 또 실결함을 찾았다

오늘 5회 배포 후 전면 점검: 서비스·에러·VRAM·큐·경보 전 축 정상(경보 21건은 전부
세션 자기 유발 — 배포·게이트·A/B 시간대와 정확히 일치·그 이전 48h는 0건).
단 하나 — **api_activity 창에서 401이 1,796건**(200은 158)이었다.

판독: **단일 외부 IP·referer `/ollama/dashboard`** 가 원격 노드 엔드포인트 4개
(`/api/his/{health,stats}`·`/api/prod/{health,stats}`)를 5초마다 폴링, 전부 401 —
**2시간에 5,760건**. 세션이 만료된 대시보드 탭이 방치된 채 영원히 폴링하는 구조다
(`fetchCached`가 401을 검사하지 않았다).

**실피해는 소음이 아니라 창 축소**: api_activity는 2000행 상한이라 이 노이즈가
행의 65%를 먹으면 관측 창이 ~28분으로 좁아진다 — 08-31에 "한계"로만 기록했던
그 28분 창의 **원인이 이것**이었다.

## 처치 — 같은 클래스 3면 일소 (클라이언트 백오프)

- `dashboard.html`: `fetchCached` → `_authCheck` 경유. 연속 401 임계 도달 시
  폴링 5초→**5분** 백오프 + "세션 만료 — 다시 로그인" 안내. **non-401 성공이 오면
  자동 복구**(카운터 리셋·5초 복원) — 다른 탭에서 재로그인하면 살아난다.
- `dashboard_all.html`: stats·health 두 fetch 모두 가드(4서버×2 폴링 페이지).
- `monitor.html`: 원격 폴러(`refreshRemoteServer` — mac/his/prod ×10s)는 타이머
  핸들이 없어 **진입 게이트** 방식(연속 401 후 5분에 1회만 통과).
- 서버 쪽은 불변 — 401 응답·기록 계약 유지(401을 안 세면 침입 시도도 안 보인다).

## 검증

- 회귀 4(`tests/test_dashboard_auth_backoff.py`): JS는 pytest 실행 검증이 안 되므로
  가드 존재·배선점·복구 리셋을 **소스 동결**(우회 리팩터링이 조용히 가드를 떨구는
  것 방지).
- ⚠️ 실효 확인은 자연 관측: 문제의 탭이 새 페이지를 로드하면(다음 방문) 가드가
  실린다 — 이후 api_activity 401 비율·창 길이로 확인(다음 세션 점검 항목).
