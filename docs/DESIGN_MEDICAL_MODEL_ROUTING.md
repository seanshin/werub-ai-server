# 의료 경로 모델 선택 — 근거와 실측

> 2026-08-04 · 전부 당일 실측 · 관련: `DESIGN_SERVING_MODES.md`(상주 정책) · `DESIGN_MODEL_SERVING.md`(VRAM 산식)

**자주 나오는 질문에 답하는 문서다.** "의료 질의인데 왜 `med` 이름 모델을 안 쓰는가",
"더 좋은 모델(35b)을 기본으로 쓰면 안 되는가".

## 1. 의료법 RAG는 왜 범용 모델(`qwen2.5:14b`)인가

### 과제 성격이 의학이 아니라 **법령 독해**다

`/api/medical-law/ask`가 하는 일은 조문 번호·항·호를 정확히 짚고 한정 조건을 보존하는 것이다.
의학 지식이 아니라 **한국 법령 텍스트 독해** 과제다.

### 실측 (2026-08-04 · 같은 근거·같은 프롬프트 · N=4)

| 모델 | 충실도 | 한글 | 지연 | 관측된 오류 |
|---|---:|---:|---:|---|
| **`qwen2.5:14b`** | **0.928** | 83% | **12~19s** | — |
| `thewindmom/llama3-med42-8b` | 0.867 | 84% | 22~30s | 🔴 무면허 벌칙을 **"500만원 이하(제90조)"** (정답 제87조의2 = 5년/5천만원) |
| `MedAIBase/MedGemma1.5:4b` | 0.917 | 86% | 21~27s | 🔴 보존기간 질문에 **제40조의3**(보관시스템) · 사본 발급 질문에 **제15조**(진료거부) |

- **med42는 `v2.124.9`가 봉합한 벌칙 오귀속을 그대로 재현**했다 — 형량을 10배 낮게 봤다.
- **MedGemma는 질문과 다른 조문을 끌어온다.** 답변도 전부 1,100자 이상으로 장황하다.

원인: med 계열은 **영어 의학 코퍼스 중심**이다(med42 = Llama3 기반, MedGemma = 영어).
한국 법령 텍스트의 조·항·호 구조에 약하다.

### 기존 측정과도 일치한다

| 측정 | 결과 |
|---|---|
| KorMedMCQA 400문항(`v2.112.0`) | qwen2.5:14b **67.5%** > qwen2.5:7b 60.5% > med42-8b 52.5% > MedGemma1.5:4b 35.2% |
| 의료 파이프라인 A/B(`v2.114.0`) | `med42` 단계가 **실경로 기여 없음** 확정(객관 동률·블라인드 judge 3.90>3.10·지연 12.8<14.7s) |

> 🔑 **"의료 특화 모델"이라는 이름이 한국어 의료 과제에서의 우위를 보장하지 않는다.**
> 세 번의 독립 측정이 같은 방향을 가리킨다.

## 2. med 계열이 실제로 쓰이는 곳

| 경로 | 모델 | 성격 |
|---|---|---|
| `/api/vision/medical/*` | MedGemma 1.5 멀티모달 | **영상 판독** — 대체 불가 |

⚠️ `medical_pin_public_models: true`(규제 가드) — **자체 파인튜닝 모델(werub\*)은 자동 경로에서
공개 모델로 대체**된다. 식약처 LLM 가이드라인 대응(`v2.124.10`).

## 3. 더 좋은 모델(35b)을 전면 도입하면 안 되는가

### 트래픽 구성이 540배 차이난다 (2026-08-04 실측)

| 경로 | 빈도 |
|---|---|
| `/api/chat` (외부 node 클라이언트) | **6.48건/분** = 9,331건/일 |
| `/api/medical-law/ask` | **17건/24h** = 0.012건/분 |

### 처리량 — 35b 전면 도입 시

`NUM_PARALLEL=2` 기준. `/api/chat` 실측 지연은 **중앙 0.66s · 평균 1.20s**다.

| 구성 | 평균 지연 | 처리 능력 | 판정 |
|---|---:|---:|---|
| **현행 14b** | 1.2s | 100건/분 | ✅ **여유 15.7배** |
| 35b + 현행 규칙 | 30.0s | 4.0건/분 | 🔴 **적체** — 요청이 능력의 1.6배 |
| 35b + 간결 규칙 | 16.0s | 7.5건/분 | ⚠️ 여유 **1.2배**(운영 마진 아님) |

체감은 **0.66초 → 16초로 24배** 나빠진다. 외부 클라이언트 타임아웃도 걸릴 수 있다.

### 품질도 경로에 따라 갈린다

| 경로 | 35b | 14b |
|---|---|---|
| RAG(근거 있음) | ✅ 제15조① 단서까지 자동 인용 | 빼먹음(그래서 부기 처치를 만들었다) |
| **근거 없는 채팅** | 🔴 "보존기간 5년"(오답) + **존재하지 않는 규정 창작** | ✅ "10년"(정답) |

**`/api/chat`은 근거가 없는 경로다.** 35b는 여기서 더 느리고 더 틀린다.

## 4. 결론 — 경로별 선택

| 경로 | 모델 | 근거 |
|---|---|---|
| `/api/chat` (주 트래픽) | **`qwen2.5:14b`** | 0.66s · 근거 없는 경로에서 35b보다 정확 |
| `/api/medical-law/ask` | **`qwen2.5:14b`**(현행) | 35b와 충실도 N=16 **전 문항 동률** — 교체 근거 아직 없음 |
| 영상 판독 | MedGemma 1.5 | 멀티모달, 대체 불가 |
| 임상 추론 앙상블 | meditron·med42·OpenBioLLM | 다관점 — 단 실경로 기여는 미확인 |

### `/ask`만 35b로 보내는 절충안

트래픽이 540배 차이나므로 스왑 비용은 **하루 약 4분**(17건 × 15s)에 그친다. 다만:

- ⚠️ **`/ask` 품질이 실제로 오르는지 확증이 없다** — N=16에서 35b와 14b의 충실도는 전 문항 동률이었고,
  35b의 우위는 `conditions_kept` 1건과 "단서 자동 인용" 관찰뿐이다.
- 스왑 4분은 **채팅 사용자에게 걸린다**(`/ask` 직후 채팅이 14b 재로드 3s를 기다림).

⇒ **교체하려면 `conditions_kept` 중심으로 N≥16을 먼저 잴 것.**

## 4-b. 파트너별 med 경로 실측 (2026-08-04)

"Cerno·Twin 요청에 med 모델이 도는가"를 실제 호출로 확인했다.

| 파트너 | 의료 접점 | 모델 | 결과 |
|---|---|---|---|
| **Cerno** | `/api/medical/dur/check` | **없음**(식약처 정본 DB 조회) | ✅ **29ms** · 병용금기 정확 검출(파록세틴↔셀레길린염산염) · 8유형 전수 |
| **Twin** | `/api/vision/medical/*` | **MedGemma 1.5** | ✅ 공개 흉부 X-ray 8.5s · 한글 구조화 판독 |
| Twin | 아바타(생리·심장EP·장기메시) | **LLM 미사용** | 물리 시뮬레이션·분할 모델 |

⇒ **Cerno는 med 모델을 전혀 쓰지 않고, Twin은 영상 판독에서만 쓴다.**

### 🔴 봉합한 결함 — 특수 토큰 누출

MedGemma가 `recommendations` 끝에 **`<start_of_image>`**를 붙여 내보냈다. 트윈이 그대로
표시하면 파트너 UI에 모델 내부 토큰이 노출된다. `_strip_special_tokens`를 **응답 수신 2곳에
단일 적용**했다(gemma/llama 계열 토큰 10종·부등호가 든 의료 수치는 보존).
라이브 재검증: 누출 0 · 판독 545자 온전.

### 🔴 봉합한 결함 2 — 진료과 명칭 오역

**빈도부터 쟀다**(N=6). 1회 관측으로 사전을 만들면 존재하지 않는 문제를 고치게 된다.

| 오역 후보 | 빈도 | 판정 |
|---|---:|---|
| **"방사선 종양학과"** | **2/6 (33%)** | 🔴 반복 → 처치 |
| "비용탈구"(늑막삼출 오역) | **0/6** | ✅ **일회성 — 처치하지 않음** |
| "경흉막"·"축착물" | 0/6 | ✅ 일회성 |

처음 관측했던 "비용탈구"는 **재현되지 않았다.** 반면 "방사선 종양학과"는 33%로 반복됐고,
**나오는 위치가 면책 문구**였다 — "전문 방사선 종양학과 진료사의 해석을 대체하지 않습니다".
방사선종양학과는 암 방사선 **치료** 진료과이고 영상 판독은 **영상의학과** 소관이라,
환자·의료진을 다른 과로 보내는 안내가 된다.

`_fix_department_terms`로 결정적 교정(진료과 명칭만 · 판독 소견의 의학 용어는 불변 ·
"방사선 치료 이력" 같은 치료 맥락도 보존). **라이브 6/6 오역 0 · 특수 토큰 0.**

### ⚠️ 남은 것 (미처치)

- `body_part: unknown` — modality는 받았는데 부위 추출 실패
- 판독 소견 자체의 용어 정확도는 4B 모델 한계일 수 있다(재현되는 오역이 관측되면 같은 방식으로 추가)

### 🔴 predict 3종 첫 측정 (2026-08-04) — 하나가 동작하지 않았다

| 경로 | 배선 모델 | 결과 |
|---|---|---|
| `readmission` | `med42-8b` | ✅ 동작 · 구조화 정상 |
| `complication` | `med42-8b` | ✅ 동작 · 구조화 정상 |
| **`adverse-drug`** | **`meditron`** | 🔴 **분석 없음 — 4/4 결정적 재현** |

`meditron`은 질문에 답하지 않았다.

```
프롬프트: 약물 이상반응 위험을 JSON으로만 답하세요(와파린+아미오다론+아스피린, 78세 여성)
meditron: "이상반응의 위험도를 계산하는 과정을 알아보세요."   ← 27자, 분석 0
```

JSON 파싱이 실패해 `{"response": <입력 에코>}` 폴백이 그대로 나갔다. 같은 입력에
`qwen2.5:14b`는 1,388자로 `individual_risks`·`duplications`·`monitoring_plan` 등 7필드를 채운다.

**처치**: `DOMAIN_MODEL_ROUTING["pharmacology"]` 1순위를 `qwen2.5:14b`로 교체.

### 🔴 함께 발견한 것 — DUR 연계가 한글을 못 읽었다

`check_drug_interaction_warnings`가 영문 토큰만 추출했다(`[A-Z][a-z]+`). **한국 의료 환경
API인데 `와파린`·`파록세틴`이 통째로 빠져** DUR 조회가 빈 목록으로 돌았다.
`/api/medical/dur/check`는 같은 입력을 29ms에 정확히 잡는데 이 경로만 0건이었다.

`medications` 원본 목록을 그대로 합류시켜 봉합했다(해석은 DUR의 `_resolve_one` 책임으로 단일화).
라이브 검증: `파록세틴+셀레길린` → `db_verified_interactions`에 **식약처DUR 정본 병합**
(세로토닌성 증후군).

> 📌 **약물 상호작용의 정본은 식약처 DUR이다.** LLM은 그 위에 설명을 붙이는 역할이며,
> 상호작용 판정 자체를 LLM에 맡기지 말 것.

### ⚠️ 부수 관측 — predict 3종의 입력 계약이 서로 다르다

```
readmission   : {patient_data: {diagnosis, lab_results, ...}}   ← 래퍼
complication  : {diagnosis, patient_info: {...}}                ← 최상위
adverse-drug  : {medications: [...], patient_info: {...}}       ← 배열
```

같은 계열인데 셋 다 다르다. 호출자가 헷갈리기 쉽다(첫 측정에서 두 개를 틀렸다). 미처치.

## 5. 이 문서를 갱신해야 하는 시점

- GPU VRAM이 24GB+로 늘 때 — 35b(14.3GB)와 14b(10.5GB)가 공존 가능해져 전제가 바뀐다
- `/ask` 트래픽이 하루 수백 건 규모로 늘 때 — 스왑 절충이 성립하지 않는다
- 한국어 의료·법령에 특화된 오픈웨이트가 나올 때 — §1의 결론을 재측정할 것
