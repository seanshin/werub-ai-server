# v2.124.17 — 검색 슬롯 중복 잠식 봉합(과다 인출 후 dedup) + id134 백로그 종결

2026-07-21 | 저우선 백로그 1번 처리 중 발견 | 관련: `docs/MEDICAL_LAW_RAG_GUIDE.md` · [[project_medical_law_rag]]

## 배경 — 백로그를 열었더니 다른 게 나왔다

저우선 백로그 1번은 **id134 코퍼스 조문경계 재청킹**(v2.124.6 기록: "제21조 청크가
조문 경계에서 절단돼 캡을 무한대로 해도 호2·3이 안 보임")이었습니다. 현 코퍼스를
진단한 결과 **재현되지 않습니다**:

- 제21조 청크 = **4,091자 단일 청크**, 항 ①~⑤ 전부·호 1~11 전부 포함(절단 없음).
- v2.124.8 거리 공간 정정(L2→cosine) 때 저장 임베딩으로 **전량 재구축**하면서 해소된
  것으로 보입니다. → **백로그 종결**(재청킹 불요).

대신 같은 진단에서 **중복 색인**이 드러났습니다.

## 발견 — 동일 원문이 검색 슬롯의 15%를 잠식

| 항목 | 실측(2026-07-21) |
|---|---|
| 코퍼스 | medical_law_knowledge 12,704청크 |
| 동일 원문 중복 | **3,013슬롯(24%)** · 1,856그룹 |
| 출처 | khidi_notice 2,900(96%) · law3dan 113 |
| 유형 | **파일 간 2,895** / 동일 파일 내 118 |
| 검색 영향 | top-8의 **15%가 중복**(최악 5/8 — "고시 시행일 부칙") |

원인은 결함이 아니라 도메인 특성입니다 — 신의료기술 평가결과 고시처럼 **차수별로
전문을 재발령**하는 고시는 같은 본문이 여러 판본에 반복 색인됩니다("제1조(시행일) 이
고시는 고시한 날부터 시행한다"는 28회).

**문제는 소비 쪽이었습니다.** `_rag_law_search`의 기존 dedup은 `top_k`만 인출한 뒤
중복을 **제거만 하고 보충하지 않아**, 법령·고시 슬롯이 줄고 그 자리를 발간물이
메웁니다(권위 하락). 근거 권위 위계(법령>고시>발간물)를 세워 둔 설계 의도가 중복 때문에
조용히 훼손되던 셈입니다.

## fix — 코퍼스는 그대로, 인출만 늘린다

- 본 코퍼스만 **`_OVERFETCH=2`배 인출 → 동일 원문 dedup → `top_k` 절단**.
- **코퍼스는 불변**으로 둡니다: 동일 본문이라도 어느 고시 판본에 실렸는지가 규제
  도메인에서 의미를 갖고(판본·시행일), 대량 삭제는 ChromaDB link_lists 폭주 이력도
  있습니다. 인출 단계 해결이 부작용 없는 최소 개입입니다.
- **eval `get_evidence_chunks`에도 동일 적용** — 검색 변경은 생성·판정 양쪽에 동시
  적용해야 한다는 v2.124.7 교훈(비대칭이면 judge가 정답 인용을 unsupported로 오판).

## 검증 (라이브 대조)

수정 전(top_k만) vs 후(2배 인출+dedup)의 **법령·고시 슬롯 수**, 6질의:

```
3 → 5   신의료기술 안전성 유효성 평가결과 고시
3 → 4   고시 시행일 부칙
5 → 5   선별급여 / 진료기록부 / 의료광고 / 평가 유예 (중복 없던 질의 = 무변화)
합계    26 → 29 (+3)
```

중복이 있던 질의만 개선되고 나머지는 그대로입니다(회귀 없음). `/ask` 라이브 응답도
정상(진료기록부 보존기간 9개 호 정확 열거·법령 인용 유지). 회귀 medlaw 계열 **85 passed**.

## 남은 관찰

이 fix는 **슬롯 수 복원**이지 관련성 개선이 아닙니다. `ctx_precision`(0.201)이 실제로
오르는지는 다음 야간 배치에서 확인해야 합니다 — 더 많은 법령 청크가 들어온다고 전부
관련 있는 건 아니므로, 정밀도가 그대로일 가능성도 정직하게 열어 둡니다.
