# v2.124.88 — fluency를 근거 없이 채점 · `actionable` 진단

> 앞선 릴리즈: `docs/RELEASE_v2.124.87.md`

`numbers_match`를 결정적으로 옮기면서 새 1위가 된 `helpfulness.actionable`(40%)을
진단하다가, **더 큰 것이 나왔다.**

## 1. 실험 — 답변을 고정하고 근거만 바꾼다

`v2.124.76`이 N=1로 관측했던 것("같은 답변인데 근거 청크 수로 `actionable`이 뒤집힘")을
6문항으로 키워 재현했다. 답변을 완전히 고정하고 근거를 1/3/5개로만 바꿔 12항목 전부를 쟀다.

| 체크 | 근거만 바꿨을 때 뒤집힘 |
|---|---:|
| `accuracy.conditions_kept` | 4/6 ← **설계대로**(근거의 조건을 지켰나) |
| `helpfulness.actionable` | 2/6 |
| **`fluency.natural_korean`** | **2/6** ← 🔴 답변만 보면 되는 항목이다 |
| 결정적 이관 3항목 | **0/6** ← 이관이 옳았음을 부수 확인 |

## 2. 🔴 judge가 **근거의 한국어**를 답변의 한국어로 읽고 있었다

같은 답변 40건을 근거 있이/없이 채점해 확정했다.

| 체크 | 근거 있이 | 근거 없이 | |
|---|---:|---:|---|
| `fluency.no_broken_text` | 25% | **0%** | 🔴 |
| `fluency.natural_korean` | 20% | **2%** | 🔴 |
| `accuracy.conditions_kept` | 30% | 72% | 근거 의존이 **설계** — 정반대 방향 |
| `helpfulness.actionable` | 40% | 48% | **근거 오염 아님** |

프롬프트에 실린 **법령 원문의 깨진 한국어**(띄어쓰기 결손·OCR 잔재·긴 열거)를 답변의
것으로 오판하고 있었다. `v2.124.77`이 `no_broken_text`의 judge 사유를
*'긴 조문 인용해 읽기 어렵다'* 로 기록한 것과 같은 현상이다.

**처치**: `fluency`만 근거 없이 **한 번 더** 채점해 덮어쓴다.

> 🔑 문구가 아니라 **프롬프트 범위**로 갈랐다. 문구 교정은 `v2.124.73`(numbers_match)과
> `v2.124.74`(형식 항목)에서 두 번 실패했다. 무엇을 **보여주느냐**는 문구로 안 바뀐다.

- 근거가 없으면 추가 호출 없음(비용) · 보조 판정 실패 시 기존 값 유지(비차단)
- `FLUENCY_WITHOUT_EVIDENCE = False`로 즉시 되돌림

### 통제군 — 완화 방향이므로 반드시 검증했다

| 입력 | natural_korean | no_broken_text | |
|---|---|---|---|
| 정상 한국어 | True | True | ✅ |
| 띄어쓰기 결손·붙여쓰기 | **False** | True | ✅ 잡음 |
| 문장 중간 절단·깨진 토큰 | **False** | **False** | ✅ 잡음 |

라이브 재채점: 이전 fluency 실패 5문항 **전부 통과**(한 건은 score 2→5).

## 3. `actionable` 40% — 근거 오염이 아니다

근거를 빼도 48%로 오히려 올랐다. 즉 `v2.124.76`의 "근거를 재는 지표" 해석은
**이 항목에는 맞지 않는다**(그 관측은 N=1이었다). 실제로 근거에 반응한 것은 fluency였다.

`actionable`("실행 가능한 구체 정보를 주는가")은 순수한 의미 판정이라 결정적 이관도 불가하다.
**미해결로 남긴다** — 법령 질의 답변이 "실행 가능"해야 하는가라는 루브릭 적합성 자체를
다시 볼 문제다.
