# Release v2.124.62 — 사전 적재 모델 설정: API + Admin UI

날짜: 2026-07-30 | 종류: feat(llm/ui) | 배포: GPU graceful HUP(NRestarts 0)

## 배경

v2.124.61에서 상주/요청-시-탑재 전환을 **API로만** 만들었다. 실제 운영에서는
"어떤 모델을 사전 적재할지"까지 고를 수 있어야 하고, 콘솔에서 보이지 않으면 쓰이지 않는다.

## 1. 사전 적재 **대상 모델**을 고를 수 있게

`llm_resident_model`(미지정 = `default_model` 따름) 추가 — `core/llm_residency.resident_model()`.

**채팅 기본 모델과 분리한 이유**: 16GB 카드에서 *품질은 14b(10.5GB)로 쓰되 상주는
7b(5.2GB)로 둔다*는 선택이 실제로 의미가 있다. 절반 VRAM으로 콜드 지연만 없앨 수 있다.

## 2. API — `GET|POST /api/models/residency` 확장

| 필드 | 설명 |
|------|------|
| `resident` | true=사전 적재 · false=요청 시 탑재 |
| `model` | 사전 적재 대상(빈 문자열=명시 해제→기본 모델 따름) |

- **존재하지 않는 모델은 400 + `available` 목록** — 오타로 지정하면 예열이 매번 실패하며
  조용히 무효가 되므로 `/api/tags`로 선검증한다(조회 실패 시엔 검증 생략=차단하지 않음).
- **모델을 바꾸면 이전 상주 모델을 먼저 반납**한다 — 안 하면 VRAM이 실제로 넘어가지 않는다.
- 응답에 `model`·`explicit_model`·`chat_default_model`·`available_models`(크기 오름차순) 추가.
  구 필드 `default_model`은 하위호환으로 유지.

## 3. Admin UI — "사전 적재 모델" 카드

`templates/admin.html` + `static/js/main.js`(인라인 템플릿 아님):

- 현재 정책·대상 모델·적재 상태(모델명·VRAM·무기한 여부) 표시
- **모델 드롭다운**(설치된 38종, 크기 표기) + **전환 버튼**(사전 적재 ↔ 요청 시 탑재)
- **"지금 반납" 버튼** — 정책은 그대로 두고 VRAM만 즉시 비운다. 요청-시-탑재 모드라도
  실트래픽이 모델을 올려두므로, **파인튜닝 직전에 쓰는 버튼**이다.
- 5분 주기 갱신(기존 카드들과 동일·신규 폴링 부담 최소)

## 4. 검증 (라이브)

| 단계 | 결과 |
|------|------|
| 없는 모델 지정 | **400** + available 38종 |
| 7b를 사전 적재로 전환 | 14b(10.51G) 반납 → **7b(5.16G) 적재** · VRAM 10,349→5,243 MiB |
| 요청 시 탑재로 복귀(+명시 해제) | `applied=unloaded` · `explicit_model=null` · 적재 0 |
| 회귀 | `tests/test_llm_residency.py` 5→**8** |

⚠️ **UI는 렌더 화면까지 눈으로 확인하지 못했다** — 콘솔이 세션 로그인 뒤에 있어(`/` → 302
`/login`) 서버에서 접근할 수 없다. 확인한 것은 ①GPU의 `templates/admin.html`에 카드 요소가
있고 ②`/static/js/main.js`가 새 함수를 포함해 서빙되며 ③카드가 호출하는 API가 라이브에서
정상 동작한다는 것까지다. **운영자 콘솔에서 한 번 봐주시면 좋겠다.**

## 5. 현재 상태

`resident=false`(요청 시 탑재) · 명시 모델 없음(기본 `qwen2.5:14b`) = 파인튜닝용 설정 유지.
