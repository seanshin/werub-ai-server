## S2 — relevance는 유사도가 아니라 순위 융합 점수였다

`/api/medical/reference`의 `relevance` = `hybrid_search`의 **가중 RRF**(Reciprocal
Rank Fusion, k=60) × 100.

RRF는 **순위만** 인코딩합니다. 1순위 문서는 내용과 무관하게 `1/(60+0)=0.0167` →
**항상 ~1.6**. 벡터 검색은 어떤 입력에도 "가장 가까운 문서"를 반환하므로, 무의미
입력도 1순위를 갖고 따라서 항상 높은 relevance를 받습니다. **호출자가 임계를 조정해
걸러내는 것이 원리적으로 불가능한 구조**였습니다.

실제 코사인은 깨끗이 갈립니다(GPU 실측, `medical_knowledge` 156문서):

| 입력 | 코사인 top-3 | 기존 relevance |
|---|---|---|
| 제2형 당뇨병 관리 | 0.691 / 0.674 / 0.628 | 1.64 |
| 고혈압 약물 치료 | 0.639 / 0.631 / 0.626 | 1.61 |
| 심혈관 위험 관리(ASCVD) | 0.570 / 0.554 / 0.540 | 1.58 |
| qwzxpk lmnrst | **0.386 / 0.381 / 0.375** | 1.0~1.5 |
| quantum blockchain protocol | **0.346 / 0.344 / 0.336** | 1.0~1.5 |

### fix

- **`_drop_weak_matches`** — 코사인 `< 0.45`이면서 키워드(FTS) 실매칭도 없는 근거 제거.
  임상(0.54~0.69)과 무의미(0.35~0.39) 사이의 빈 구간을 기본값으로 잡았습니다.
  config `medical_reference_min_similarity`(0=비활성) 무재배포 조정.
- **컨텍스트 구성 *전*에 적용** — LLM도 노이즈 근거를 보지 않습니다([표7-1] 오인용의
  근원 차단).
- **FTS 용어 실매칭은 게이트 제외** — 벡터 상위에 못 든 정확 용어 매칭을 잃지 않기 위함.
- **`confidence`(코사인 0~1) 추가**, `relevance`는 값·의미 그대로 유지 —
  트윈의 기존 1.3 필터가 갑자기 전부를 버리는 사고를 막기 위한 하위호환.
- (b) LLM 리랭킹은 미채택: 게이트만으로 노이즈가 0이 되고 지연·비결정성만 늘어납니다.

무의미 입력 **5건 → 0건**, 임상 질의 **5/5 유지**(conf 0.535~0.691). 회귀 5건.

## S1 — source는 데이터가 없어서가 아니라 하드코딩이었다

`sources[]`의 `source`가 `""`로 **코드에 하드코딩**돼 있었습니다. 색인 메타데이터에는
발행기관이 이미 들어 있었습니다(`대한당뇨병학회`·`대한고혈압학회`·`ACC/AHA 고혈압
가이드라인`·`WHO ICD-10 / 한국표준질병분류 KCD-8` 등).

- `build_context_with_citations`(client/rag.py)가 `source`·`version`을 인용에 실어
  보내도록 수정 — 이 함수를 쓰는 모든 소비자가 함께 이득.
- reference 응답에 `source`·`version` 노출.
- ⚠️ URL·DOI는 코퍼스가 보유하지 않습니다(학회 지침을 정리한 텍스트). 발행기관까지가
  현재 제공 가능 범위이고, 링크 보강은 코퍼스 작업 항목으로 남습니다.
