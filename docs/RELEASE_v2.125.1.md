## 2. 🔴 `code` 필드가 문서 계약을 위반하고 있었다

골든셋을 만들다 찾았다. `/api/code/generate`가 응답 `code`에 LLM 원문을 그대로 실었다 —
마크다운 펜스와 코드 뒤의 **설명 산문**까지. 그런데:

- **문서 계약 위반**: `docs/CODING_API_GUIDE.md`의 응답 예시는
  `"code": "from fastapi import Depends, HTTPException..."` = **순수 코드**다.
- 🔴 **검사 대상과 반환 값이 달랐다**: `syntax_valid`·`security_scan`은 **펜스를 벗긴
  `code_block`**을 검사한 값인데 그 `code_block`은 **반환되지 않았다**.
  ⇒ 호출자가 받은 문자열을 그대로 `ast.parse`하면 실패하는데 플래그는 `true`였다.

처치: `code` = 추출 블록(폴백 내장) · `raw` = 원문 보존. `refactor`·`convert`도 같은 형태라
**함께** 고쳤다("한 곳에서 고친 결함은 같은 클래스 전 경로를" — v2.124.65).

## 3. 🔴 캐시 가드 — 같은 클래스가 세 번째, 그리고 **처치가 한 번 뚫렸다**

배포 게이트가 `writing[draft-not-empty-korean]`으로 막았다.

**증상**: `/api/writing/draft`가 **0.0초에 0자**. 프롬프트를 **한 글자만** 바꾸자
**3.8초·493자·한글 74%** — 0.00N초는 캐시 히트의 판별 신호다.

**원인**: 캐시 가드가 `if response:`뿐이었다. 그런데 **호출자는 그 값을 그대로 쓰지 않는다** —
`force_korean`을 한 번 더 태운다(5곳). 비한국어 응답은 필터가 **통째로 비우므로**
"원문이 안 비었다"고 캐시하면 그 뒤로 **영원히 빈 초안**이 나간다.
실측: 영문 문장 → `force_korean` 후 **0자**.

### 그리고 첫 처치가 뚫렸다

`force_korean(response).strip()`으로 고쳤더니 이번엔 **`'[]\n[]'`(5자)**가 통과했다 —
비어 있지 않을 뿐 **한글이 하나도 없다**. 초안 API가 그것만 반환했다.

🔑 **판정을 두 번 약하게 걸어 두 번 뚫렸다.** "비었나"는 **저장하는 쪽이 아는 조건**이고,
소비자가 필요로 하는 건 **쓸 수 있는 한국어**다. `_cacheable()` 순수 함수로 분리하고
**한글 존재**를 요구한다.

📌 이 클래스는 오늘만 세 번째다(`/ask` 실패 캐시 v2.124.85 · `_medical_generate` 깨진 JSON ·
이 건). **"같은 클래스"라고 알아본 뒤에도 판정 기준을 소비자에게 맞추지 않으면 다시 뚫린다** —
클래스를 인식하는 것과 올바른 조건을 고르는 것은 별개였다.
