## 사안1 — id360(07-26): 근거 인출 일과성 실패가 무성으로 삼켜져 배치 위양성

**증상**: core 첫 문항 "진료기록부 보존기간은?"이 faith 0.615·contradicted 2·
mc_conflicts 3·**ctx_precision 0.0**·처리 107s(평소 25~29s). 과거 전 배치에서 이 문항은
chunks=10·faith 1.000이었는데 이 배치만 **chunks=4**.

**포렌식**:
- 저장된 근거 4청크 = 자보 제29조·국민건강보험법 제96조의4·의료급여법 제11조의2·심사청구
  보관 — **전부 타법 "보존" 조문**이고 정답(의료법 시행규칙 제15조)이 없음.
- 답변 자체는 제15조 보존기간 표를 **정확히** 제시(환자명부 5·진료기록부 10·처방전 2년 등)
  → judge가 "근거에 없는 주장"으로 정확한 답변을 감점 = **위양성**.
- 라이브 재현: 동일 질의가 제15조를 **rank-1(0.765)** 인출 = 검색 로직·코퍼스 정상.
- 원인 = 배치 시점 eval 프로세스(콜드 캐시·프레시 파이썬)의 본 코퍼스 첫 검색이
  **임베딩 콜드 로드 timeout(30s)** 류 일과성 예외 → `get_evidence_chunks`의
  `except Exception: pass`가 **무성 스킵** → 발간물 컬렉션만 근거로 남음. 107s가 잔흔.
  생성(/ask) 측은 정상(답변의 제15조 표가 원문 어투 = 컨텍스트/시드 확보) — 오염은
  평가 근거만.

**fix** (`scripts/eval_faithfulness.py get_evidence_chunks`):
- 컬렉션 블록별 **1회 재시도**(3s 대기) + 실패를 stderr 로그(`eval_nightly.log`에 표출:
  1차 실패 재시도 / 재시도 소진 시 "근거에서 제외됨(판정 오염 주의)").
- 측정 불능은 판정 결과가 아니다 — 무성 실패 금지, 최소한 로그에 보여야 드릴다운에서
  즉시 분류 가능.
- 회귀 `tests/test_eval_evidence_retry.py` **2**(재시도 복구·소진 시 graceful+로그).

## 사안2 — id355(07-25): 관련성 judge 방향 편향이 "경우·요건 열거형" 문형에 잔존

**증상**: "의료인이 환자의 진료 요청을 거부할 수 있는 경우는?" — 정답 조문
**제15조(진료거부 금지 등)가 top-1으로 인출됐는데** 관련성 judge가 10청크 전부 무관
판정(ctx_precision 0.0)·sufficiency 0.0. v2.124.28(id277)에서 봉합한 프레이밍 편향의
잔존 문형.

**결정적 재현·실험** (N=5):
- 현행 `_REL_SYS`(시스템 지시): 제15조 → **5/5 False**.
- 시스템 지시 강화판(경우·요건 문형 명시 추가): 여전히 **5/5 False** — **시스템 프롬프트
  지시만으로는 이 문형에서 미반영**이 결정타.
- 같은 지시를 **청크별 유저 프롬프트에 병기**: 제15조 **5/5 True**·무관 디코이 3종
  (청구 전자문서·제27조 무면허·제46조 진료의사 선택) **전부 False 유지**·id277(제21조)
  회귀 없음(True 유지).
- sufficiency 동일 병기: 제15조 단독 근거가 no(0.0) 3/3 → **partial(0.5) 3/3**
  (원칙 금지 조문은 허용 경우 판단의 기준을 제공 — no는 과소).

**fix** (`core/retrieval_eval.py`):
- `_REL_DIRECTION_NOTE` 신설 — 방향 무관 지시를 청크별 **유저 프롬프트에 병기**
  (시스템 `_REL_SYS`는 유지). sufficiency 프롬프트에도 동일 병기.
- 회귀 `tests/test_retrieval_eval.py` +2(유저 프롬프트 지시 존재 가드 — 시스템 단독
  회귀 방지).
