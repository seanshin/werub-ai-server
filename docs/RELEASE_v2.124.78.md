## 3. heavy tier → EXAONE 4.0 32B 전환

`hf.co/LGAI-EXAONE/EXAONE-4.0-32B-GGUF:Q4_K_M`(19GB). Ollama 0.32.5가 `family: exaone4`로
인식하며 공식 GGUF를 직접 pull할 수 있다.

**grounded A/B N=8**(오늘 프로토콜·문항별 대응):

| 모델 | 충실도 | 품질 | 지연 |
|---|---:|---:|---:|
| `qwen3.6:35b-a3b` | 0.975 | 4.38 | **32s** |
| **`EXAONE-4.0-32B`** | 0.967 | **4.62** | 64s |

| 지표 | 부호검정 |
|---|---|
| 충실도 | 2승 1패 5동 · p=1.000 |
| 품질 | 0승 **5패** 3동 · **p=0.062** |

> ⚠️ **N=8은 불일치 5쌍이 최선이라 구조적으로 유의 판정이 불가능하다**(최소 가능 p=0.062).
> "유의하지 않다"가 아니라 **"표본이 작아 판정 불가"**로 읽어야 한다. 확정하려면 N≥16.

**지연 2배는 구조 차이다** — dense 32B(19GB)가 16GB VRAM을 넘어 CPU 오프로드를 타는 반면,
qwen3.6은 **MoE(활성 3B)**다. heavy tier가 지금까지 빨랐던 이유가 여기 있었다.

### 라이선스

EXAONE 4.0 = **EXAONE 1.2 - NC**. §1과 같은 **비상업적 사용 전제**로 운용한다.
복귀 경로는 config 한 줄(`heavy_model` → `qwen3.6:35b-a3b`)이다.

### ⚠️ 근거 없는 호출에서는 창작이 나온다

`/api/chat/heavy`는 **RAG 근거를 붙이지 않는 경로**다. 라이브 확인에서 시행규칙에 없는 내용을
생성했다("조산 기록 20년"·"치과의원 5년" — 조산기록부는 5년). 근거를 준 A/B에서는 충실도
0.967이었다. **사실성이 필요한 호출은 근거를 함께 넘길 것.**

## 6. 🔴 EXAONE 4.0 heavy 전환 철회 — N=16에서 재현 실패

N=8의 품질 우위가 **소표본 착시**였다. 같은 프로토콜로 N=16 재측정:

| 지표 | N=8 | **N=16** |
|---|---|---|
| 품질 | EXAONE **0승 5패** (p=0.062) | **5승 4패 7동 · p=1.000** |
| 충실도 | 2승 1패 (p=1.000) | qwen3.6 **4승 0패** (p=0.125) |
| 평균 | 4.62 vs 4.38 | **4.44 vs 4.48**(역전) |

충실도 평균도 **0.940 vs 0.984**로 EXAONE이 열세다. 지연은 2.4배(27s → 64s).

⇒ **`heavy_model`을 `qwen3.6:35b-a3b`로 복귀**(config + 코드 기본값). 라이선스도 NC → Apache-2.0.
**모델 파일은 보존**한다(19GB · 디스크 277GB 여유).

> 📌 오늘 두 번째로 같은 교훈을 얻었다 — 오전엔 오염된 하네스가, 오후엔 작은 표본이 결론을
> 뒤집었다. **N=8에서 불일치 5쌍이면 최소 p가 0.062라 애초에 유의 판정이 불가능**했다.
> heavy tier 후보는 **N≥16으로 시작**할 것.
