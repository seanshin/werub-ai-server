## 1. Phase 1-d — LLM 호출을 한 층으로 모았다

| 단계 | 대상 | 지점 |
|---|---|---:|
| 1 | `routes/medical_law._generate` | 1 |
| 2 | `core/faithfulness`·`core/llm_judge` | 4 |
| 3 | `/ask/stream` + **스트림 인터페이스 신설** | 1 |
| 4 | counseling·writing·korean·spellcheck + **chat 인터페이스 신설** | 8 |
| 5 | orchestrator·novel | 5 |
| 6 | 임베딩(`client/rag`·`routes/coding`) | 3 |

어댑터 5종: `generate` · `stream` · `chat` · `chat_stream` · `embed`.
**S2 seam 경유 11파일**, 모델명 하드코딩 257 → 154.

### 설계에서 지킨 것

**페이로드는 한 곳에서 만든다.** `_payload(stream=…)`·`_chat_payload(stream=…)`를
스트림/비스트림이 공유한다. 두 경로가 각자 본문을 만들면 조용히 갈라진다 —
v2.124.59에서 `/api/chat`만 `options`·`think`·이미지 처리가 빠져 **호출자가 준 값이
200 응답과 함께 버려졌고 로그에 흔적조차 없었다**.

**커넥션 회수는 어댑터가 보장한다.** 클라이언트 조기 종료 시 `GeneratorExit`이 어댑터까지
전파된다. 정상·조기종료·깨진 줄·HTTP 오류 네 경로를 회귀로 고정했다.

**실패 규율을 층별로 갈랐다.**

| 층 | 실패 |
|---|---|
| `generate`/`chat` | `Result(ok=False)`에 실어 반환 |
| `stream`/`chat_stream` | **던진다**(토큰을 이미 낸 뒤엔 결과 객체 자리가 없다) |
| 프로덕션 라우트 | 라우터 배선 실패 시 **구 경로로 강등** |
| **평가 경로** | **강등 금지** — 측정 도구가 조용히 다른 구성으로 돌면 그 배치를 믿을 수 없다 |

**정본이 둘이 되지 않게 했다.** 표는 값을 적지 않고 **어디서 가져올지**만 적는다:

```
eval.faithfulness_judge  → model_from: judge_config:faithfulness
orchestrator.general_chat → model_from: tools_config:general_chat
```

표에 값을 또 적으면 config로 모델을 바꿔도 `/api/models/routing`이 **옛 값을 광고**한다 —
규제 트랙은 그 엔드포인트 폴링으로 모델 교체를 감지하기로 한 계약이다(v2.124.12).

**임베딩은 값을 동결했다.** `requires_reindex`가 재색인 비용을 코드에 남긴다
(rag: medical_law 13,002 + medical_pub 15,285 + werub_docs + edu_docs).
seam은 '바꿀 수 있게' 만들되 **'바꾸기 쉬워 보이게' 만들면 안 된다**.

## 2. 🔴 이관이 드러낸 실결함 3건

### 2-a. 이관 자체가 Fair Queue를 우회했다 (내 결함·G4 회귀가 잡음)

`_ollama_session`은 단순 세션이 아니라 **`_GatedOllamaSession`**이다 —
`ChatFairQueue(max_global=3, max_per_user=1)` 슬롯을 잡는다(v2.24.1).
어댑터가 자기 세션을 만들자 **큐 제어가 통째로 빠지고** keep-alive 풀도 잃었다.

증상이 명확했다: **실패를 주입했는데 실제 LLM 응답이 돌아왔다.**

📌 내 동등성 테스트가 이걸 못 잡았다 — `_post`를 패치해 **페이로드만** 비교했기 때문이다.
**"페이로드가 같다"는 이관의 필요조건이지 충분조건이 아니다.** 같은 요청을 다른 통로로
보내면 그 통로에 걸린 제어가 전부 빠진다. 이후 전 지점에서 **호출자의 세션·base를 전달**한다.

### 2-b. 깨진 JSON을 캐시가 고정시켰다 (이관과 무관·G1 스모크가 잡음)

`/api/medical/predict/adverse-drug`가 구조화 필드 없이 **3/3 결정적으로** 실패했다.
두 겹이었다:

1. 재기동 직후 **콜드 캐시 상태의 첫 생성**이 깨진 JSON을 냈다(14b는 캐시 콜드/웜에 따라
   긴 생성이 갈린다 — v2.124.20에서 규명한 성질)
2. `_medical_generate`가 그것을 **캐시에 저장**했다. 가드가
   `not response.startswith("Error")`뿐이라 "에러가 아니면 성공"으로 봤다

결정적 증거: 같은 프롬프트에서 **나이만 70→71로 바꾸자**(캐시 키가 달라지자) 즉시 정상.

📌 `/ask` 실패 캐시(v2.124.85)와 **같은 클래스**가 이 경로에 남아 있었다.
처치=`accept=` 판정(JSON 계약 15곳 배선). 🐞 첫 구현이 틀렸고 회귀가 잡았다 —
`force_json`은 **실패해도 dict를 돌려준다**(`{fallback_key: 원문}`)라 센티넬 키가 필요했다.

### 2-c. `routes/coding.py`만 `num_ctx`가 없었다

v2.86.12에서 고친 §1-2 OOM 결함이다 — 임베딩이 전역 8192를 먹으면 KV가 4.5GB로 불어
상주 14b(10.5GB)와 겹쳐 16GB에서 터진다. `client/rag.py`는 그때 고쳤는데 **이 경로는
빠져 있었다.** 어댑터가 항상 ctx를 싣는 구조라 **이관이 곧 봉합**이었다.

📌 **"한 곳에서 고친 결함은 같은 클래스 전 경로를 쓸 것"**(v2.124.65) — 하루에 두 번 확인.

## 3. 🔴 iMac 위임이 한 건도 안 되고 있었다

운영자 제보("iMac 정보가 대시보드에 제대로 안 나옴")를 추적해 나온 **두 겹의 결함**.
터널 3채널·워커·설정·breaker가 전부 정상이라 **화면은 초록**이었고, `위임 0`만 유일한 신호였다.

**① 동점을 목록 순서가 갈랐다.** iMac이 `mem_pressure=warn`(free 7.2GB·45% — macOS의
평상 상태)일 때 소프트 패널티 **5.0**이 remote+`prefer_imac` 보너스 **5.0**과 **정확히
상쇄**돼 두 노드가 **10.00 동점**이 됐고, 안정 정렬이 후보 첫 항목(gpu-local)을 남겼다.
⇒ **`prefer_imac`이 조용히 '절대 imac 아님'으로 뒤집혔다.**

**② 비교의 한쪽만 재고 있었다.** 로컬 실행은 `on_dispatch_end`를 타지 않아 gpu-local의
`latency_ewma_ms`가 **영원히 비어 있었다**(지연 0 = 무한히 빠름) — 동점이 풀릴 여지조차 없었다.

처치=동점은 **정책이 가른다**(`_policy_rank`, 하드 게이트는 여전히 정책을 이긴다)
+ `nodes.record_latency`(inflight·breaker 미개입). 라이브에서 위임 발생 확인.

⚠️ **미처치(보고만)**: iMac 첫 호출이 **5,971ms**(콜드 모델 적재)라 그 한 샘플이 EWMA에
남아 다시 로컬로 돌아간다. 웜은 58~92ms이므로 한 번 데워지면 이길 텐데,
**데워질 기회를 못 얻는 콜드 스타트 함정**이다. 해법(패널티 가중치·EWMA 감쇠·주기 프로브)은
**측정 없이 고르지 않는다**.

## 4. 골든셋 — 1도메인 → 6도메인

| 도메인 | 케이스 | 성격 |
|---|---:|---|
| medical_law | 5 | 기존 |
| **counseling** | 6 | 안전 계약 + 금지 신호 |
| **korean** | 5 | 정답 있음(맞춤법 규칙) |
| **writing** | 6 | **과거에 실제 깨졌던 것**(v2.105.0 번역 가드 3종) |
| **medical_data** | 8 | 🔑 **LLM 미개입 — 가장 견고** |
| **story** | 4 | 지시 도달 확인 |

스모크 **64 → 132체크**. S3(평가 있는 도메인) 목표 ≥4 **달성**.

**같은 날 2차 확장** — coding 7 · 의료 정본 +5 · 의료법 +4 = **7도메인 50케이스 · 스모크 173**:

| 추가 | 성격 |
|---|---|
| **coding 7** | 코드는 **파싱된다** — 정답 검증이 가능한 드문 도메인 |
| **의료 정본 +5** | 🔴 **데이터 손실 감시**(v2.124.92 치료재료 -35% 무성 손실) — 규모 하한 |
| **의료법 +4** | 이력이 가장 많은데 통제군이 5개뿐이었다 |

⚠️ 넣지 않은 것: **novel**(project_id 필요 — 스모크마다 상태 누적) · **STT**(octet-stream이
Bearer 없으면 415 — 게이트 키 배선 선행) · **RAG 보안**(이미 `smoke_rag`가 덮는다).
📌 **60은 목표치이지 할당량이 아니다** — 값 없는 케이스로 숫자를 맞추면 게이트만 느려진다.

### 도메인마다 성격이 다르다

**의료 정본**은 식약처·심평원 DB 조회라 결과가 결정적이다(DUR 조회 **0.006초**로 확증).
모델을 갈아끼워도 불변인 **가장 견고한 게이트**다. 🔴 미검출(처방 사고)과 과검출(경보 피로)
**양방향**을 다 건다. ⚠️ 정본이 갱신되므로 신호는 개별 품목이 아니라 **구조와 분류**로 잡았다.

**상담·스토리**는 정답이 없어 `forbidden`과 **지시 도달**만 본다. 인물명('해무리')·
세계관('윤슬탑') 같은 고유 토큰은 창작 변동과 무관하게 잡힌다.

### 🔴 라이브 확인이 세 번 내 단정을 뒤집었다

작성 전 라이브 확인(v2.124.92 규율) 덕에:

1. **상담 `no-diagnosis`의 `signals_any`가 틀린 이유로 통과했을 것** — '전문|의사'가 하필
   **자격 허위 주장 문장**('저는 전문 의사입니다')에도 들어 있었다 → 비웠다
2. **korean `unchanged-correct-text`** — '세 시'를 단정했으나 실제로는 '오후 3시'로
   **표기만 정규화**(뜻 보존). 지키려던 건 뜻 보존인데 단정이 표면을 봤다 → 택일로
3. **writing `polish`** — '건강검진'→'건강 검진' 정규화. 같은 실수 두 번째라 바로 잡았다

### 🔴 내가 만든 통제군이 릴리즈 배포를 막았다 (그리고 그게 맞았다)

릴리즈 커밋 배포에서 `korean[unchanged-correct-text]`가 **131/132**로 차단했다.
같은 입력('오후 세 시')에 교정 결과가 **실행마다 달랐다** — 10:12엔 `오후 3시`,
11:09엔 `오후 세시`. 처음엔 '세 시'를 단정했다 실패해 택일 3종으로 고쳤는데
**네 번째 변형**이 나왔다.

⇒ 시각 표기 단정을 **제거**했다. 변형을 계속 덧붙이는 건 두더지 잡기이고,
**흔들리는 통제군은 게이트를 죽인다** — 오늘 네 번 내린 판단을 내가 만든 통제군에도
적용했다. 뜻은 어느 표기든 보존되므로 안정적인 명사(오늘·회의·오후) 생존으로 충분하다.

📌 게이트가 **아홉 번째**로 막았고, 이번 대상은 **나 자신**이었다.

이어진 재배포는 **열 번째**로 막혔다 — `test_get_db_concurrent_no_deadlock`이
`ERR:database is locked`로 실패했다. 그런데 **그건 데드락이 아니라 busy_timeout 만료**다.
32스레드가 한 파일에 동시 쓰기를 시도하는 건 프로덕션(단일 워커·분산된 쓰기)보다 훨씬
가혹한 합성 조건이고, 배포 중 ollama가 CPU를 점유하면 5초 안에 못 잡는 스레드가 나온다
(단독 재실행은 3/3 통과·0.06초).

⇒ **락 경합과 데드락을 분리**했다. 락 외의 오류는 여전히 즉시 실패이고,
`busy_timeout` 불변식은 `test_get_db_pragmas`가 **결정적으로**(>=5000) 이미 지킨다.
여기서는 그 값이 사라졌을 때 나타날 신호(**대다수 실패**)만 잡는다.
📌 **완화가 아니라 오분류 교정**이다 — 이 구분을 못 하면 원칙이 통제군을 깎는 핑계가 된다.

### 🔴 관측했으나 **통제군에 넣지 않은 것**

상담 AI가 **"죄송합니다만, 저는 전문 의사입니다"**라고 답했다(자격 허위 + 자기모순).
그러나 재현이 **10회 중 1회**고 나머지는 오히려 정확했다("저는 전문적인 의사나 치료사가
아닙니다"). ~10%로 흔들리는 게이트는 **꺼지는 게이트**다 — 기록만 남기고 처치는 빈도 측정 후.
탐지 정규식은 **통제군으로 검증**해 주석에 박아 뒀다.

## 5. 배포 게이트가 체계로 섰다

`scripts/deploy.sh` 5단계가 오늘 **여덟 번 배포를 막았다**. 그중 실결함 2건, 나머지는
게이트 자신의 품질 문제였고 전부 고쳤다:

| 막은 것 | 성격 | 처치 |
|---|---|---|
| 게이트 자기 배선(`No module named 'core'`) | fail-closed 작동 | `sys.path` + 회귀 |
| **이관이 Fair Queue 우회** | **실결함** | 세션 전달 |
| 소스 문자열 계약 테스트 | 테스트 품질 | 거동 검사로 |
| **깨진 JSON 캐시 고정** | **실결함** | `accept=` 판정 |
| pull 실패가 로그에 안 남음 | 절차 | `FAIL pull` 기록 |
| G4에 라이브 테스트 혼입 | 게이트 계층 | `SKIP_NETWORK_TESTS=1` |
| 동시성 배리어 타임아웃 | 오분류 | `BrokenBarrierError` 제외 |
| **`database is locked`를 데드락으로 집계** | 오분류 | 락 경합과 데드락 분리 |

**G4를 결정적으로 만들었다**(1584 passed · 3분41초 → **2분11초**). 라이브 모델 검증은
5단계 스모크의 몫이고, 마침 같은 날 korean 골든셋이 그 커버리지를 가져갔다.

## 6. 📌 측정 방법론 — 재채점 모드 ≠ 배치 모드

이관 검증 중 **품질 점수가 올라** 되돌릴 뻔했다. 같은 답변·같은 코드인데:

| 실행 | overall | 재현성 |
|---|---:|---|
| 배치 모드(생성+채점) | 4.6375 | N=1 |
| 재채점 전용 ×3 | 4.7062~4.7188 | **±0.006** |

차이 **+0.075 · 40문항 중 22건 뒤집힘**. judge 노이즈 바닥은 훨씬 작다(뒤집힘 8).

🔑 **구 judge 코드로 돌려도 똑같이 움직였다** — 코드가 아니라 **실행 방식** 탓이다.
이 통제가 없었으면 멀쩡한 이관을 되돌렸을 것이다.

⇒ **`--reuse-answers` 결과를 배치 추세선에 얹지 말 것.** 비교는 같은 실행 방식끼리만.
