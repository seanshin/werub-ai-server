# RELEASE v2.118.1 — DUR 병용금기 일반명 검출 fix (의료 안전)

**날짜**: 2026-07-05
**헤드라인**: DUR 병용금기(약물 쌍) 검출이 **일반 성분명으로 실패**하던 버그 수정. 의료 수집 자료
점검 중 발견 — 임상적으로 중요한 병용금기를 놓칠 수 있는 안전 관련 결함.

---

## 증상
- `파록세틴 + 셀레길린`(일반명) → 병용금기 **0건** ❌
- `파록세틴 + 셀레길린염산염`(salt 정식명) → 병용금기 **검출** ✅ ("세로토닌성 증후군")

## 근본원인
식약처 병용금기 API는 **a측 성분명(INGR_NAME)을 빈값으로 반환**(코드만 제공)하고 b측만 **salt
정식명**(예: `셀레길린염산염`)을 제공한다. 그 결과 `dur_interaction.a_name`이 **전량 빈값**이 되고,
`core/dur._resolve_one`의 이름→코드 해석이 **exact-match**만 수행해:
- a_name 빈값 → a측 이름 해석 불가
- b_name = salt 정식명 → 일반명(`셀레길린`)이 `셀레길린염산염`과 exact 불일치

→ 일반명 입력 시 성분코드로 해석되지 않아 쌍 매칭 실패 = **병용금기 누락**. (단일성분 금기/주의는
정상 — dur_single이 일반명을 보유.)

## 수정 (`core/dur.py`)
`_resolve_one` 이름 해석에 **salt 관대 매칭** 2단계 추가:
1. **`_strip_salt()`** — salt/수화물 접미(염산염·황산염·수화물·베실산염 등 27종) 제거 → 원문 + 기본형
   양방향 exact 매칭(dur_interaction b_name / dur_single).
2. **접두 LIKE 폴백** — exact 실패 & 입력 ≥3자면 `base%`로 b_name·dur_single.ingr_name 매칭
   (`셀레길린` → 저장 `셀레길린염산염`). 3자 미만은 과매칭(false positive) 방지로 제외.

a_name이 빈값이라 실효 매칭은 b_name·dur_single 경로에서 발생.

## 검증
- 회귀 `tests/test_dur.py` **18→22**(`_strip_salt`·**a_name 빈값+일반명 실버그 재현**·대칭·과매칭 가드).
- 🎯 **라이브(실데이터)**: `파록세틴+셀레길린`(일반명) → **병용금기 1건 "세로토닌성 증후군"**(수정 전 0건).
  무관 조합(`파록세틴+메트포르민`) → 0건(오탐 없음). graceful HUP·NRestarts 0·health 200.

## 영향 / 하위호환
- 병용금기 검출 **정확도 향상**(누락 감소). exact 매칭 우선이라 기존 정탐 무변경.
- 과매칭 가드(≥3자 접두)로 false positive 억제. DUR=자문 보조·실시간 차단 아님(최종 판단 처방의·약사).
