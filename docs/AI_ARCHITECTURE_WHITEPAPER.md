## 1. 개요 — 무엇을 하는 시스템인가

WeRU.B AI 서버는 **자체 보유 GPU 서버(온프레미스)에서 구동되는 통합 AI 플랫폼**이다.
LLM 대화·의료 자문 보조·의료 데이터 정본 서비스·이미지 생성/판별·음성(STT)/회의 분석·
한국어 분석/교정·스토리/소설 창작·게임 NPC·HR 법무·환자 디지털 트윈까지를 **단일
진입점(REST API)**으로 제공한다. 외부 상용 LLM API에 데이터를 보내지 않으며, 모든 추론이
기관 인프라 내부에서 일어난다.

**규모 스냅샷 (v2.125.39, 2026-09-06)**

| 축 | 값 |

| LLM/특화 모델 | **43종** (후보 보존분 포함 · 전부 라이브 배선) |

## 2. 목표 — 무엇을 이루려는 시스템인가

이 시스템이 지향하는 목표는 다섯 가지이며, 각각에 대응하는 구조적 장치가 있다.

| 목표 | 왜 | 이를 보장하는 구조 |
|---|---|---|
| **① 데이터 주권 — 진료·개인 데이터의 완전한 내부 처리** | 의료 데이터는 외부 상용 API로 보낼 수 없다 | 전 추론 온프레미스 · 외부 provider 기본 비활성 · `policy: local_only`를 코드가 강제(fail-closed) |
| **② 의료 안전 — 환각이 아니라 정본에 근거한 답** | 의료에서 환각은 환자 안전 문제다 | 결정적 의료 라우터(LLM 우회) · 공식 데이터 453,222행 · RAG 인용 강제 · 인용 무생성 보장 |
| **③ 외부 의존 0의 완결형 플랫폼** | 서비스 연속성·비용·데이터 유출 3중 이유 | 웹 검색(SearXNG)·맞춤법(자체 LLM)·임베딩·STT·이미지까지 전부 자체 구동 |
| **④ 한국어 품질 — 영·중 혼입 없는 자연스러운 한국어** | 오픈 모델의 한국어는 방치하면 혼탁해진다 | force_korean 전/후처리 계층 · 한국어 분석 22메트릭 · 문자 단위 정화(내용 보존) |
| **⑤ 연동 가능한 플랫폼 — 사람이 아니라 기계가 읽는 표면** | HIS·그룹웨어·ERP·외부 에이전트가 붙는다 | OpenAPI 전수 문서화 · 의료 카탈로그 API · MCP 표준 · OpenAI 호환 · 버전 응답 헤더 |

의료 AI의 역할 한계도 목표의 일부다: **자문 보조이지 처방 차단 시스템이 아니며**, 최종 판단은
의료 전문가에게 있다. 이 한계는 마케팅 문구가 아니라 응답 필드(면책 고지)와 스펙에 명시된다.

### 3.2 환자 디지털 트윈 아바타 (R1/R2/R3 — 외부 트윈팀 공동)

전부 **비식별**(지오메트리·스칼라장·파형만, PHI 0) 자문 보조용.

- **R1 — 0D 다계통 생리 시뮬레이션**: 약물 반응 시계열 8지표(혈압·심박·혈당 등)와 계통 간
  커플링(신배설→약동학→심혈관). 순수 numpy·CPU(GPU 무경합)·결정적·미저장.
- **R2 — 의료영상→장기 3D 메시**: NIfTI → TotalSegmentator 분할 → marching cubes →
  **glTF(.glb)** 표준 메시. 다장기(폐·심장·신장·간). 비동기 202+폴링.
- **R3 — 심장 전기생리**: 표면 메시 위 eikonal 활성화 시간(LAT) + 현상학적 12-lead ECG를
  glTF per-vertex 속성으로 임베드. 병태 프리셋(각차단·비대·QT 연장). 정점 정렬을 구조적으로
  보장(재매핑 불요), 출력 인터페이스 불변 유지로 향후 정밀 솔버 교체 가능.

## 4. 설계 철학 — 여섯 가지 원칙

이 시스템의 구조는 추상적 이상이 아니라 **실제로 터졌던 사고에서 역산한 원칙**들로
짜여 있다. 각 원칙은 문서가 아니라 코드와 테스트가 강제한다.

### 4.1 온프레미스 · 데이터 비유출
진료·환자 데이터가 외부로 나가지 않는다. LLM(Ollama)·임베딩(bge-m3)·웹 검색(SearXNG
자체 호스팅)·맞춤법(자체 LLM)·STT(faster-whisper)까지 전부 내부 구동. 외부 provider
어댑터는 존재하지만 **기본 비활성**이며, 의료·PHI 경로는 `policy: local_only`로 표시되어
어댑터가 이를 **거부**한다(fail-closed). 원칙의 집행자가 사람이 아니라 코드다.

### 4.2 정본 근거 · 결정적 라우팅 (모델보다 데이터)
의료 안전이 걸린 질의(약물 상호작용·대체조제·의약품 정보·의료법)는 LLM의 확률적 판단을
거치지 않고 **공공기관 공식 데이터를 결정적으로 조회**한다. LLM은 그 결과를 한국어로
자연화하는 역할에 머문다. "모델을 키우는 것"보다 "정확한 데이터에 근거를 묶는 것"이
환각 억제의 1차 수단이다.

### 4.3 무성 실패 금지 (No Silent Failure)
이 시스템에서 가장 자주 재발한 결함 클래스는 **"200인데 빈 결과"**였다 — 필터가 내용을
통째로 지우거나, 워커가 이형 키로 응답해 위임이 조용히 전부 실패하거나, HTTP 오류가
빈 문자열로 뭉개지는 류. 처치 원칙: 오류는 **오류로 드러낸다**(502·스트림 error 줄·
로그 1줄), 실패를 캐시하지 않는다, 컨텍스트 초과는 무성 절단이 아니라 오류다.
전 경로 일괄 소거를 두 차례(v2.125.15~16) 수행했고 회귀가 패턴 재유입을 차단한다.

### 4.4 측정 선행 · 사전 등록 (Measure First)
비용이 드는 처치는 **채택/기각 기준과 노이즈 바닥을 측정 전에 못 박고**(사전 등록),
측정 후 판정한다. 기획서에 적혀 있다는 것은 이행 이유이지 효과의 증거가 아니다 —
실제로 "재시도 로직"이 사전 등록 실측(N=30, 전환 0/8)으로 기각된 사례, OCR 폴백이
사전 등록 기준 재측정으로 채택된 사례가 공존한다. 탐지기는 결함을 세기 전에
**라벨 통제군**으로 먼저 검증한다(과소·과대·위양성 전부 겪었다).

### 4.5 계약의 명시화 — 버전·스키마·헤더
모든 응답이 자기 버전을 말한다: `X-API-Version`(빌드)·`X-API-Contract`(하위호환이 깨질
때만 오르는 계약 축)·`X-API-Commit`. 두 축을 분리한 이유는 한 숫자로 섞으면 연동자가
매 배포마다 호환성을 의심하게 되기 때문이다. API 표면은 전수 감사로 미선언 태그 0·
인증 표기 누락 0을 유지하며, 응답 스키마는 **코드에서 기계적으로 확정된 것만** 싣는다
(추측한 스키마는 없느니만 못하다 — 확정 불가 경로는 비워 두고 연동 수요 발생 시 채운다).

### 4.6 의료 AI는 자문 보조
모든 의료 응답에 면책 고지를 강제한다(응답 **필드**로 나가며 스펙에도 명시). 실시간
처방 차단 시스템이 아니고, 최종 판단은 의료 전문가에게 있다. 식약처 LLM 디지털의료기기
가이드라인 대응 체계(근거 무생성 보장·모델 판본 고정·파라미터 재현성)를 갖춘다.

## 6. 소프트웨어 스택 — 그리고 그 형태인 이유

| 계층 | 기술 | 왜 이 형태인가 |
|---|---|---|
| 앱 서버 | Flask + Gunicorn | **gthread 96스레드 · worker 1 · `preload_app=False`** — SSE 장기 연결과 SQLite의 공존을 위한 구성. preload fork가 SQLite `-shm`을 상속해 발생한 실제 장애에서 확정 |
| 추론 엔진 | Ollama (버전 고정 운용) | 엔진 업그레이드는 "최신 존재"가 아니라 **결함 수정·기능 필요가 트리거** — 기본값이 조용히 바뀌는 사고(repeat_penalty 1.1→1.0)를 사전 등록 A/B로 잡아낸 뒤, 엔진 기본값 의존을 없애는 핀(pin) 작업을 선행조건으로 걸었다 |
| 벡터 검색 | ChromaDB (cosine) | HNSW + bge-m3 임베딩. 컬렉션 단위 격리·보호 컬렉션 접근 차단 |
| 정형 데이터 | SQLite (WAL) 위성 DB 다수 | 도메인별 분리(queue·medical·notice·eval·story…) — 단일 DB 잠금 경합 회피. busy_timeout·WAL 일관화 |
| 전문 검색 | SQLite FTS5 | 벡터 검색과 병합하는 하이브리드 검색의 키워드 축 |
| 웹 검색 | SearXNG (자체 호스팅) | 외부 검색 API 의존 0 |
| 이미지 생성 | ComfyUI(9모델) + SANA 0.6B 사이드카 | SANA는 상주 LLM과 **co-resident 가능한 유일 무스왑 이미지 경로**(warm 1.14s) |
| STT | faster-whisper (large-v3 배치·medium 실시간) | GPU 상주 경합을 피하는 int8_float16 양자화 |
| 관측 | Prometheus `/metrics` + 자체 대시보드 | 큐·토큰·오류율·upstream 분리 계측 |

**Ollama를 그대로 노출하지 않는 이유** (핵심 5건 — 전체 11항목은 `DEVELOPER_GUIDE.md` §1):

1. **전역 컨텍스트의 무성 절단** — `OLLAMA_CONTEXT_LENGTH`는 프로세스 전역이라 큰
   프롬프트가 에러 없이 잘린다. `/v1`은 패스스루가 아니라 **변환 프록시**로 만들어
   요청별 `num_ctx`를 주입하고, `/api/generate`는 길이 추정으로 고정 버킷 상향.
2. **임베딩까지 전역 컨텍스트를 먹어 OOM** — bge-m3에 `num_ctx=2048` 명시(4.5GB→1.16GB).
3. **OpenAI 도구 호출 포맷 불일치** — arguments가 문자열(OpenAI) vs 객체(Ollama).
   양방향 변환 없이는 에이전트 루프가 1스텝에 죽는다.
4. **멀티모달 입력 경로 정규화** — data URI 접두 제거·content 배열 변환·원격 URL은
   SSRF 표면이라 400. 경로마다 달랐던 이미지 처리를 한 곳으로.
5. **thinking 모델의 빈 응답** — 사고 토큰이 `num_predict` 예산을 소진하면 본문이
   0자가 된다. 사고형 모델 감지 시 예산 상향 + `think:false` 주입, 그래도 비면 502
   (무성 실패 금지).

## 7. LLM 추상화 — 여섯 층, 각 층은 하나의 결정만

호출 경로를 관심사별 층으로 분리했다. LiteLLM 같은 외부 추상화의 도입을 전수 비교로
검토한 결과 **신규 이득이 거의 없어 기각**했고(대부분 자체 구현이 선재), 갭이던
"task→모델 매핑 + 정책 강제"만 신설했다.

| 층 | 모듈 | 정하는 것 |
|---|---|---|
| ① task 라우팅 | `core/model_router.py` | **역할 이름 → 모델**. 코드에 모델명을 쓰지 않는다 (`medical_law.answer` → 모델). 미등록 task는 즉시 실패(오타가 조용히 다른 모델을 타는 것 방지) |
| ② provider 게이트웨이 | `core/llm_gateway.py` | 모델명 → 공급자. 외부 provider는 기본 비활성 |
| ③ 복원력 | `core/llm_resilience.py` | 적응형 타임아웃·서킷 브레이커·동일 요청 병합 |
| ④ 상주 정책 | `core/llm_residency.py` | 어느 모델을 VRAM에 유지할 것인가(무재배포 전환 API) |
| ⑤ 노드 분산 | `core/orchestrator/dispatch.py` | 어느 기계에서 처리할 것인가 (GPU ↔ iMac) |
| ⑥ 도메인 라우팅 | `core/medical_router.py` | 안전 민감 질의 → 결정적 도구 (LLM 우회) |

**층 경계의 규율** (이관 과정에서 사고로 확정):
- 한국어 후처리·응답 캐시·도메인 복원력은 **seam 위**(호출자 소관) — 필터가 seam 안에
  있으면 내용을 지우는 사고가 경로 전체로 퍼진다.
- `keep_alive`·`think`·`format`은 **seam 안** — 모델 선택과 결합돼 있다.
- 라우팅 표는 값을 이중으로 적지 않는다 — `model_from` 참조로 정본을 한 곳에 유지
  (안 그러면 config로 모델을 바꿔도 라우팅 API가 옛 값을 광고한다).
- **임베딩 교체는 별격** — `requires_reindex: true`가 재색인 비용을 코드에 남긴다.
  seam은 "바꿀 수 있게" 만들되 "바꾸기 쉬워 보이게" 만들면 안 된다.

에이전트 경로가 깨진다 — 삭제 판단의 1차 근거는 사용 통계가 아니라 **코드 배선 여부**다.

### 8.2 VRAM 예산과 상주 정책

16GB는 "상주 14b(10.5GB) + 그 외 하나"만 허용한다. 이 제약 아래의 설계 선택:

- **상주(fast-lane)와 heavy tier의 분리**: 기본 채팅은 상주 모델로 TTFT 0.13초를
  보장하고, 대형 모델은 별도 경로(`/api/chat/heavy`)에서 상주를 일시 축출→하이브리드
  구동→응답 후 자동 복원한다. single-flight 락으로 동시 heavy는 409.
- **모델 크기 산정식(자체 실측 보정)**: Q4_K_M ≈ **5.0 bits/weight**(설치본 역산,
  일반표 4.5보다 정확) → `크기(GB) = 파라미터(B) × 5.0 ÷ 8`. 필요 RAM ≈ 모델크기 −
  GPU적재분 + 10GB. 현 구성의 수용 상한 **33GB**, RAM 128GB 증설 시 **131GB**.
- **MoE만 실용적**: 대형 dense는 50~88초/문항, MoE(활성 3B)는 58 tok/s 실측.
  단 30B급 MoE는 상주 14B 대비 품질 이득이 없음을 grounded A/B로 확인 —
  **체급 상향의 트리거는 RAM 증설 + 대형 MoE의 grounded 우위 선입증**이다.
- **경량 fast lane**: 3B 이하 모델은 큐 우선순위가 자동 상향된다.

### 8.3 신규 모델 도입 체크리스트 (요약)

파라미터/활성 파라미터 → 크기·필요 RAM 산정 → 하드웨어 가부 판정 → 라이선스(계열
단위로 뭉뚱그리지 않기 — 라이선스상 금지 조항이 있는 모델은 해당 표면에만 배선하는
것 자체가 준수 장치) → thinking 여부(`think:false` 경로 확인) → **grounded A/B로 현
구성 대비 우위 선입증**. 최신 버전의 존재는 정보이지 트리거가 아니다.

## 9. 오케스트레이션 — 세 겹의 라우팅

### 9.1 노드 오케스트레이터 (기계 선택)

호출자는 GPU 서버 하나만 부른다. 오케스트레이터가 작업 capability(detect·stt·mark·
embed)와 노드 실시간 상태로 최적 노드에 배정한다.

- **하드 게이트**(제외 조건): 미도달 · capability 없음 · 서킷 브레이커 open ·
  메모리 critical · 발열 스로틀 · heavy 락
- **소프트 가중**: 진행 중 요청 수 · 지연 EWMA + 히스테리시스(핑퐁 방지)
- **서킷 브레이커**: 연속 실패 → open(30s) → half-open 프로브 → 자동 close
- **정책 스위치**: `auto | prefer_imac | prefer_gpu | gpu_only`(킬스위치) —
  무재배포 리로드
- 응답의 `ml.engine` 필드로 처리 노드가 드러난다(스키마는 동일 — 호출자는 무시 가능)

### 9.2 대화 오케스트레이션 (4단 폴백)

```
사용자 메시지
  ① 결정적 의료 라우터 — 식약처/HIRA 정본 도구 직접 실행 (LLM 우회·모델 무관)
  ② 워크플로우 인텐트 매칭
  ③ Tool Calling — qwen3:8b가 도구 판단·조합 (최대 5회 반복)
  ④ 일반 챗 — qwen2.5:14b
```

Tool Calling은 3종 프로토콜을 쓴다: `ai://`(내부 API) · `llm://`(직접 LLM) ·
`search://`(SearXNG). 도구 정의는 `config/tools.json` 설정 파일 기반(무재배포 리로드).

### 9.3 외부 에이전트 연동 (MCP · OpenAI 호환)

- **MCP 서버**: JSON-RPC 2.0 Streamable HTTP(`POST /mcp`) — Claude·GPT·Cursor 등
  외부 에이전트가 이 서버의 도구를 표준으로 직접 호출.
- **OpenAI 호환 `/v1/chat/completions`**: 패스스루가 아닌 **변환 프록시** —
  요청별 `num_ctx` 주입·tool_calls 양방향 변환·SSE 스트리밍.

## 10. RAG와 의료 데이터 정본 — 환각 억제의 구조

### 10.1 검색 설계

- **하이브리드**: 벡터(ChromaDB+bge-m3, cosine) + 키워드(SQLite FTS5) 병합
- **권위 위계**: 법령 > 고시 > 상대가치 > 발간물 — 하위 문헌이 상위 법적 근거를
  밀어내는 권위 역전을 가중치로 방지
- **인용 강제**: 근거 인용 없는 위험도 상향 금지. 인용(citations)은 전부 실재 DB
  검색 산출물 — **LLM이 인용 문자열을 생성하는 경로가 없다**
- **테넌트 격리**: 벡터·FTS 양 경로에서 조직 단위 격리. 보호 컬렉션은 일반 RAG
  API에서 접근 차단(5개 진입점 공통)

### 10.2 수집 파이프라인의 신뢰성 장치 (실사고에서 확립)

의료법 코퍼스(KHIDI 고시)는 자동 수집되며, 다음 가드는 전부 라이브 사고의 산물이다:

- **삭제 tombstone**: 중복 정리로 지운 문서를 수집기가 "신규"로 재다운로드해 삭제가
  하루 만에 무효화되는 churn을 상태 기록으로 봉쇄. 다른 첨부(fileId 상이)는 통과.
- **파싱 붕괴 가드**: 폰트 결손 PDF가 한글 2.1% 쓰레기로 색인돼 검색을 오염시킨 사고 →
  ≥500자 & 한글<5%면 색인하지 않고 보고. 임계 5%는 코퍼스 146파일 전수 실측의 분리대역.
- **OCR 폴백**: 파싱 붕괴 문서는 이미지 렌더→OCR 모델로 복구 시도하되, **산출물도
  동일 게이트를 통과할 때만** 색인(`parse_method:"ocr"` 표기). 사전 등록 측정으로 채택.
- **중복 판정의 도메인 규칙**: 전문(통합본)과 일부개정(diff)은 중복이 아니라 **상보
  관계**, 일부개정은 회차마다 별개 문서다 — 이를 무시한 초기 dedup이 최신 개정분을
  지우려 한 것을 통제군 검증이 막았다. 구버전 전문은 정책상 보존(과거 시점 질의 대비).
- **안전 갱신**: 외부 API 동기화는 전량 수신+건수 정합 검증 후에만 교체. 장애 시
  기존 정본 보존. 결측은 0이 아니라 **null**로 보고(0으로 세면 "방금 갱신"으로 보인다).

### 10.3 연동 진입점 — 기계가 읽는 카탈로그

`GET /api/medical/catalog`가 보유 데이터셋·건수·최신성·서빙 엔드포인트를 기계가 읽는
형태로 제공한다(데이터셋별 fail-open — 하나 깨져도 나머지는 산다). 집계만 노출하며
PHI·본문은 싣지 않는다.

## 11. 품질 평가 프레임워크 — 9축 폐루프

외부 평가 API 0(judge=상주 로컬 모델), 야간/온디맨드 배치로 자기 품질을 계측한다.

| 축 | 방법 |
|---|---|
| 성능/정확도 | 표준 벤치 정답률(KorMedMCQA·KMMLU) |
| 충실도/환각 | RAG groundedness — **주장 단위** supported/unsupported/contradicted |
| 교차검증 | judge와 **다른 체크포인트**의 2차 의견(모델 이종성) — 불일치는 검토 트리거 |
| 가치/품질 | G-Eval 4차원 + **이진 체크리스트 12항목**(이진이 5점 척도보다 안정) |
| 검색 품질 | context precision + 근거 충분성 — "검색 vs 생성" 층 분리 |
| judge 신뢰도 | 같은 답변 반복 채점의 flip rate — 판정기 자체를 계측 |
| 종합 지수 | 결정적 합성 0~100 (내부 추세 관리용) |
| 법령명 오귀속 | 순수 함수 탐지 — judge가 원리적으로 못 보는 축(내용만 대조하므로) |
| 단서 오독 | 배제 부기 "(X 제외)"가 근거에선 허용인 경우 — 좁게·fail-open |

**설계 요점**:
- 질의 풀은 **일자 기반 결정적 회전**(같은 날=같은 세트·7일 주기 전체 커버) — 랜덤을
  배제해 재현 가능성을 확보.
- **미측정과 0건을 가른다** — 결측을 0으로 세면 축이 깨끗해 보인다. 무효 배치는 null.
- **추세 단절점을 API·화면에 표기** — judge 교체·거리 공간 변경·근거 라벨 도입 등
  측정계 변경 시점을 명시해 전후 비교 오독을 막는다.
- 집계 지표가 비슷하면 **원문을 연다** — 법령명 오귀속 8건 중 7건이 충실도 1.000으로
  통과한 실측이 이 규율의 근거다.

### 배포 파이프라인

커밋 → GPU pull → import dry-run → 재기동 → **스모크 게이트 177항목**(의료 라우팅·
비전 통제군·medlaw 검색·기능 스모크) → 실패 시 차단. 회귀 스위트 2,094건이 배포 전
로컬에서 돈다. 흔들리는(확률적) 신호는 게이트 베이스라인에 넣지 않는다 — 사람이
게이트를 끄게 만들어 진짜 신호까지 묻기 때문이다.

## 12. 보안 설계

### 12.1 인증·인가 계층

- **API 키 Bearer 인증**(외부) + localhost 바이패스(내부 신뢰 경계) — 키 생성·관리는
  localhost 전용. 만료·로테이션(신·구 병행)·검증 캐시 TTL 60s.
- 관리자 기능은 admin 게이트, 워커 간 통신은 별도 토큰(`worker_auth`) — 사용자 키와
  기계 토큰의 분리.
- 비밀번호는 per-user salt + PBKDF2-SHA256(200,000회)·레거시 무중단 lazy 재해싱.

### 12.2 공격 표면 방어 (라이브 재현으로 확정한 것들)

- **경로 순회**: 파일명 입력은 basename+realpath 봉쇄 — 형제 경로가 이미 옳게 푼
  패턴의 미적용 지점을 전수 소거(설정 파일·SECRET_KEY 유출 재현 후 봉합).
- **localhost 위조**: 내부 디스패치가 `REMOTE_ADDR=127.0.0.1` 컨텍스트를 합성하던
  경로에 명시적 allowlist — 접두사 검증이 아니라 등록·디스패치 양 지점 검사.
- **SSRF**: 외부 URL 입력은 IP 리터럴 정적 검사 + 공개 IP 리졸브 검사(블로킹 DNS는
  요청 핸들러가 아니라 백그라운드 워커에서 — gthread 고갈 방지). 요청 경로에서 원격
  URL fetch 자체를 400으로 거부하는 경로 다수.
- **CORS**: 화이트리스트만 반사. "로컬 요청이면 임의 Origin 반사" 같은 편의 절은
  터널 사용 개발자의 브라우저를 통한 관리 표면 노출이라 제거.
- **레이트리밋**: 전역 120/min + 고비용 15경로 개별 per-key 리밋 — 임계는 7일 실측
  피크의 6배 이상으로 설정(추측 금지). 실시간 연쇄 계약 경로는 의도적으로 제외하고
  그 제외를 회귀가 동결.
- **401 계약**: 인증 실패는 세지 않으면 침입 시도도 안 보인다 — 서버는 401을 유지하고,
  폴링 폭주는 클라이언트 백오프로 처치(연속 401 → 5분 백오프+재로그인 안내).

### 12.3 프라이버시

- PHI 비저장 모드(기본 토글 + 요청 단위 `store=false`) · 의료 카탈로그는 집계만.
- 의료영상 3D 메시는 지오메트리만 추출(DICOM 태그 미임베드·임시 파일 폐기).
- AI 생성물 표시(AI 기본법 §31): 가시 워터마크 + 메타데이터 + C2PA 서명 자동 부착.

## 13. 신뢰성 공학 — 반복 결함 클래스와 운영 규율

수백 릴리즈에서 **같은 모양으로 재발한 결함**을 클래스로 정리해 새 작업의 1차 의심
목록으로 쓴다. 구조 문서에 이것을 싣는 이유는, 이 시스템의 설계 다수가 이 클래스들의
방어 장치이기 때문이다.

1. **200인데 빈 결과**(무성 실패) — 로그에 흔적이 없어 사람이 눈치채는 경로가 없다.
2. **탐지기는 양방향으로 틀린다** — 세기 전에 라벨 통제군에 먼저 건다.
3. **기준은 측정 전에 못 박는다** — 한 번 잰 값 위에 처치를 설계하지 않는다.
4. **효과 미확인 처치 금지** — "붕괴 0"은 결함 없음이 아니라 이 N에서 미관측이다.
5. **캐시 조건은 쓰는 쪽이 통과시킨다** — 실패를 캐시하면 결정적으로 재현된다
   (0.00N초 응답 = 캐시 히트가 판별 신호).
6. **측정층을 먼저 특정한다** — 검색·생성·판정 중 어디가 나쁜지 소거로 가른 뒤
   모델을 의심한다.
7. **한 곳에서 고친 결함은 같은 클래스 전 경로를 쓴다** — 형제 경로 스윕.

**운영 장치**: systemd+cron watchdog(자동 재기동·포렌식 덤프) · graceful drain(재시작
시 SSE 구독자 종료 통지) · SSE 구독자 상한/IP당 축출 · 재부팅 후 자동 검증
(`post_reboot_verify` — 커널·드라이버·VRAM 상주·서비스 전수) · GPU 드라이버 무인
업그레이드로 인한 **CPU 폴백 감지**(`/api/ps`의 `size_vram`이 판별 신호 — health 200이
이 상태를 못 본다는 실사고에서 추가).

## 16. API 플랫폼 — 표면 관리

- **디스커버리**: `GET /openapi.json` · `/.well-known/openapi.json` ·
  `/.well-known/ai-plugin.json` · Swagger UI(`/docs`) — 외부 도구가 클라이언트를
  자동 생성할 수 있다.
- **표면 감사 기준선**: §15 표 참조. 응답 본문 스키마는 연동 표면부터 수동(추측 금지) —
  잔여는 내부·창작 도메인이라 실제 연동 요청 발생 시 그 경로만 채운다(문서 1건당
  연동 가치의 기울기를 명시하고 멈춘 결정).
- **표면 분리**: 일반 AI(`/api/general/*`)와 의료 AI를 **코드가 분리**한다 — 모델
  allowlist(의료 모델 지정 시 400)·전문 자문 안내 프롬프트·라이선스 제약 모델의
  표면 한정 배선. 회귀가 이름 패턴으로 재유입을 차단.
- **버전 응답**: 모든 응답에 `X-API-Version`/`X-API-Contract`/`X-API-Commit` —
  subprocess 없이 `.git` 직접 판독·캐시, 부착 실패가 응답을 막지 않음.
