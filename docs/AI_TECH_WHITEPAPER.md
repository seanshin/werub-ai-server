# WeRU.B AI 플랫폼 기술백서

> **버전** v2.106.1 · **문서 성격** 홈페이지/파트너 공개용 기술 소개 자료(화이트페이퍼)
> **대상 독자** 기술 검토자·연동 파트너·규제 검토 담당
> **요지** 자체 호스팅(온프레미스) GPU 인프라 위에 구축한 통합 의료·일반 AI 플랫폼의 기반 구조, 채택 표준·규격, 오케스트레이션 설계, 보안·개인정보 보호 원칙을 정리한다.

## 1. 개요 (Executive Summary)

WeRU.B AI 플랫폼은 **자체 보유 GPU 서버에서 직접 구동되는 온프레미스 AI 시스템**이다. 외부 상용 LLM API에 환자·진료 데이터를 전송하지 않고, 모든 추론을 **기관 내부 인프라**에서 수행한다. 이를 통해 데이터 주권(data sovereignty)과 개인정보 비유출을 구조적으로 보장한다.

플랫폼은 다음을 단일 시스템으로 제공한다.

- **대화형 AI**(LLM) — 의료 상담 보조·일반 챗·상담(counseling)·문서 작성
- **의료 정보 정본 서비스** — 식약처/심평원(HIRA) **공식 데이터에 근거(grounding)**한 약물 상호작용(DUR)·의약품 정보·약가·의료법 자문
- **영상·이미지 AI** — 의료영상 장기 분할·3D 메시 생성, AI 이미지 생성·판별
- **환자 디지털 트윈 아바타** — 의료영상→장기 3D 메시(glTF), 0D 다계통 생리 시뮬레이션, 심장 전기생리(표면 LAT + 12-lead ECG) — 외부 디지털트윈팀과 공동 구축
- **음성·회의 분석** — STT(음성→텍스트)·화자 분리·회의 요약, 실시간 회의 자막·통역(STT+번역) 위임
- **API 플랫폼** — 592개 이상의 REST API와 표준 디스커버리(OpenAPI) 제공

핵심 설계 원칙은 ① **온프레미스·데이터 비유출**, ② **공식 데이터 정본 근거(환각 억제)**, ③ **의료 AI는 자문 보조 — 최종 판단은 의료진**, ④ **표준 규격 준수**(FHIR·MCP·C2PA·OpenAPI 등)이다.

## 2. 기반 구조 (Infrastructure)

### 2.1 하드웨어 토폴로지

```
┌──────────────────────────────────────────────┐
│  GPU 서버 (Ubuntu, NVIDIA RTX 5080 16GB)       │
│   ├─ Flask + Gunicorn (애플리케이션 서버)        │
│   ├─ Ollama 추론 엔진 (LLM 35종)                │
│   ├─ ChromaDB (벡터 검색) + SQLite (정형 데이터)  │
│   └─ SearXNG (실시간 웹 검색, Docker)            │
│                  ▲                              │
│                  │ 동적 작업 위임 (capability)    │
│                  ▼                              │
│  Apple Silicon 워커 (iMac M1, Metal)            │
│   └─ AI 이미지 판별 · STT 오프로딩                │
└──────────────────────────────────────────────┘
        │ HTTPS (nginx 리버스 프록시)
        ▼
   외부 클라이언트 / 병원 정보시스템(HIS) / 홈페이지 컨시어지
```

- **주 추론 노드**: NVIDIA RTX 5080(16GB VRAM) GPU 서버. 상주 LLM(qwen2.5:14b) + 온디맨드 모델 로딩.
- **보조 워커 노드**: Apple Silicon(M1) — Metal 가속으로 AI 판별·STT 등 경량/특화 작업을 위임 처리(이기종 분산).
- **이기종 아키텍처 통합**: CUDA(서버)·MPS(Apple)·CPU를 단일 디바이스 추상화 계층으로 통합하여 동일 코드베이스로 운용.

### 2.2 소프트웨어 스택

| 계층 | 기술 | 비고 |
|------|------|------|
| 애플리케이션 | Flask + Gunicorn(gthread) | SSE 스트리밍 안정화·graceful drain |
| 추론 엔진 | Ollama | 로컬 LLM 서빙, 35모델 |
| 벡터 검색 | ChromaDB | HNSW 인덱스, 임베딩 `bge-m3` |
| 정형 데이터 | SQLite (WAL) | 작업 큐·세션·의료 정본 데이터 |
| 웹 검색 | SearXNG (Self-hosted) | 외부 검색 API 의존 0 |
| 역방향 프록시 | nginx | HTTPS 종단·외부 접근 |
| 관측 | Prometheus 메트릭 | `/metrics` 노출, Grafana 연동 |

### 2.3 자체 호스팅 원칙

- **외부 AI API 미사용**: 진료·환자 데이터를 외부 상용 LLM(OpenAI 등)에 전송하지 않는다. 모든 모델은 기관 인프라 내에서 구동.
- **오픈소스·자체 구축**: 기능은 라이선스 적합 오픈소스를 자체 구축하여 외부 서비스 의존을 최소화한다(웹 검색·맞춤법·임베딩·STT 포함).
- **경로 등급의 코드 강제**: 의료·PHI·규제 경로는 `policy: local_only`로 표시되며, 외부 provider 어댑터가 이를 **거부**한다(fail-closed). 원칙을 문서가 아니라 코드가 지킨다.

### 2.4 LLM 추상화 층 — 벤더 종속을 만들지 않는 구조

모델·공급자를 바꿔야 할 때를 대비해 호출 경로를 계층으로 분리한다. 각 층은 **하나의 결정만** 담당한다.

| 층 | 정하는 것 |
|---|---|
| task 라우팅 | **역할 이름 → 모델**(`medical_law.answer` → 모델). 코드에 모델명을 쓰지 않는다 |
| provider 게이트웨이 | 모델명 → 공급자(로컬 Ollama / 외부 API). 외부는 기본 비활성 |
| 복원력 | 적응형 타임아웃·서킷 브레이커·동일 요청 병합 |
| 상주 정책 | 어느 모델을 VRAM에 유지할 것인가(16GB 제약) |
| 노드 분산 | 어느 기계에서 처리할 것인가(GPU ↔ Apple Silicon) |

**교체 가능성은 검증으로 보장한다.** 엔진·어댑터가 지켜야 할 계약을 회귀 테스트로 고정하고
(컨텍스트 길이 요청별 적용·구조화 출력 제약·도구 호출 포맷·멀티모달 입력 등),
후보를 같은 기준으로 실측한 뒤에만 채택한다.

> 상세: `docs/DESIGN_LLM_ABSTRACTION.md`

## 3. AI 모델 구성 (Model Fleet)

총 **35종**의 LLM/특화 모델을 도메인별로 라우팅한다. 모델 키우기(확률적)보다 **정확한 데이터에 근거한 결정적 라우팅**을 의료 안전 원칙으로 채택한다.

| 도메인 | 대표 모델 | 역할 |
|--------|-----------|------|
| 일반 챗·종합 | qwen2.5:14b (상주) | 한국어 자연화·종합 응답 |
| 도구 호출(Tool Calling) | qwen3:8b | 의도 판단·도구 조합 |
| 의료 추론 | med42(1순위), MedGemma 1.5 | 임상 QA·추론 보조 |
| 의료 영상 | medgemma:4b (비전) | 영상 텍스트 해석 보조 |
| 코딩 | qwen3-coder:30b | 코드 생성 |
| 상담 | mindwell + qwen3:8b | 상담 전문 + 한국어 자연화 |
| 임베딩 | bge-m3 | RAG 벡터화(다국어) |

> 모델 선정은 한국어·의료·코딩 벤치마크에 근거하며, 16GB VRAM 제약 하에서 품질·속도·메모리 공존을 종합 평가하여 결정한다.

## 4. 오케스트레이션 (Orchestration)

### 4.1 노드 오케스트레이터 — 단일 진입점 자동 분산

호출자는 **GPU 서버 하나만 호출**한다. 오케스트레이터가 작업 capability와 양 노드의 실시간 상태(부하·지연·발열·서킷브레이커)를 평가해 최적 노드에 자동 배정하고, 실패 시 GPU 로컬로 무중단 폴백한다.

- **하드 게이트**(발열/메모리 임계·브레이커) + **소프트 가중**(진행 중 요청·지연 EWMA) + 히스테리시스
- **불변식**: 노드 미설정/미도달 시 기존 동작 100% 보존, 폴백 예외 전파 0
- 현재 라이브 위임: AI 이미지 판별·STT(음성 인식) → Apple Silicon 워커

### 4.2 대화 오케스트레이션 — 3단계 폴백

```
사용자 메시지
  ① 결정적 의료 라우터  (식약처/HIRA 정본 도구 직접 실행 — 모델 무관)
  ② 워크플로우 인텐트 매칭
  ③ Tool Calling (qwen3:8b가 도구 판단·조합, 최대 5회)
  ④ 일반 챗 (qwen2.5:14b)
```

- **결정적 의료 라우터**: 의료법·약물 상호작용·대체조제·의약품 정보 등 안전 민감 질의는 LLM의 확률적 판단을 거치지 않고 **공식 데이터 도구를 결정적으로 호출**한다. 스트리밍·비스트리밍 양 경로 모두 적용되어 응답이 모델에 좌우되지 않는다.
- **Tool Calling**: 내부 API(`ai://`)·직접 LLM(`llm://`)·웹 검색(`search://`) 프로토콜을 통해 도구를 호출·조합한다.

### 4.3 MCP (Model Context Protocol) 서버

외부 AI 에이전트(Claude·GPT·Cursor 등)가 본 플랫폼의 도구를 **MCP 표준**으로 직접 호출할 수 있도록 JSON-RPC 2.0 엔드포인트를 제공한다(프로토콜 버전 `2025-03-26`, Streamable HTTP).

## 5. 지식 증강 검색 (RAG)

LLM 환각을 억제하기 위해 응답을 **근거 문헌에 결합(grounding)**한다.

- **하이브리드 검색**: 벡터 유사도(ChromaDB + `bge-m3`) + 키워드 전문검색(SQLite FTS5)을 병합.
- **멀티 컬렉션**: 법령·고시·상대가치·발간물 코퍼스를 분리 색인 후 검색 시 병합.
- **근거 권위 위계**: 법령 > 고시 > 상대가치 > 발간물 순으로 가중치를 부여하여, 하위 문헌이 상위 법적 근거를 밀어내는 권위 역전을 방지한다.
- **인용 강제**: 의료 자문·위험 평가는 **근거 인용이 없으면 위험도 상향을 금지**(환각 방지)하며, 모든 응답에 출처를 동봉한다.
- **테넌트 격리**: 벡터·전문검색 양 경로에서 조직/소유자 단위 격리를 강제하여 타 기관 비공개 지식이 노출되지 않도록 한다.

**안전 설계**:
- **안전 갱신**: 외부 API 동기화 시 전량 수신 성공 + 건수 정합성 검증 후에만 교체한다. API 장애·부분 응답 시 **기존 정본을 보존**하여 빈 테이블·오염을 방지한다.
- **자동 동기화**: 주기 스케줄러가 식약처/HIRA 정본을 갱신하며, 소스별 상태·시각·건수를 메타로 관측한다.

### 6.1 환자 디지털 트윈 아바타 (R1 / R2 / R3)

외부 디지털트윈팀과 공동 진화하는 **환자 아바타** 파이프라인을 제공한다. 모두 **비식별**(지오메트리·스칼라장·파형만, 환자식별정보 PHI 0)이며 자문 보조용이다.

- **R1 — 0D 다계통 생리 시뮬레이션**: `POST /api/medical/physiology`. 순수 numpy·CPU(LLM/GPU 무경합)·결정적·미저장. 약물 반응 시계열(혈압·심박·혈당 등 8지표)과 계통 간 커플링(신배설→약동학→심혈관, 경구혈당강하제 동역학)을 산출한다. 약물명 한글/브랜드→INN 정규화.
- **R2 — 영상→장기 3D 메시**: `POST /api/vision/medical/organ-mesh`. 서명 URL(NIfTI.gz) → 비동기 202+폴링. 의료영상 장기 분할(TotalSegmentator) → 표면 메시(marching cubes) → **glTF(.glb)** 표준 메시. 폐·심장·신장·간 등 다장기. VRAM 직렬화·온디맨드, 지오메트리만 추출(DICOM 태그 미임베드).
- **R3 — 심장 전기생리(EP)**: `POST /api/medical/cardiac-ep`. 심장 표면 메시 위에서 **eikonal 활성화 시간(LAT)**(측지거리·이방성 전도·다중 개시부)과 **현상학적 12-lead ECG**(이동 쌍극자 forward, fs500/2500ms)를 계산하여 glTF에 per-vertex 속성(`_LAT`)으로 임베드한다. **정점 정렬을 구조적으로 보장**(export 메시 정점에서 직접 계산 → 트윈 측 재매핑 불요). 병태 프리셋(좌·우각차단, 좌·우심실비대, QT 연장 등). CPU 대리모델(현상학적 surrogate)이며, 출력 인터페이스를 불변으로 유지한 채 향후 정밀 솔버로 교체 가능하다.

> 양측 E2E 라이브 검증을 완료하였으며, 표준 glTF 로더에서 정상 동작함을 확인하였다.

## 7. 채택 표준·규격 (Standards & Specifications)

| 분류 | 표준/규격 | 적용 |
|------|-----------|------|
| 의료 상호운용성 | **HL7 FHIR R4** | 의료 데이터 교환 |

### 7.1 AI 생성물 표시(투명성)

AI 기본법(§31, 2026.1.22 시행) 대응으로 생성 이미지에 **가시 워터마크("AI 생성·AI-generated")**와 **메타데이터**를 자동 부착하고, **C2PA 디지털 서명**(self-hosted 인증서 체인)으로 출처를 증명한다. 또한 업로드 이미지의 AI 생성 여부를 **판별**(메타/C2PA 판독 + 화소 분류)하는 기능을 제공한다.

## 8. 보안·개인정보 보호 (Security & Privacy)

의료 데이터를 다루는 시스템으로서 다음을 구조적으로 적용한다.

- **PHI 비저장 옵션**: 진료 입출력을 저장하지 않는 모드(기본 비저장 토글) 및 요청 단위 opt-out(`store=false`)을 제공한다.
- **테넌트(기관) 격리**: RAG 지식베이스·전문검색을 조직 단위로 격리하여 교차 노출을 차단한다.
- **인증**: API 키 기반 Bearer 인증, 키 만료·로테이션(무중단 신·구 키 병행), localhost 바이패스.
- **비밀번호 보호**: per-user 랜덤 salt + PBKDF2-SHA256(200,000회) 단일 소스화. 레거시 해시 무중단 lazy 재해싱.
- **SSRF 방어**: 외부 URL 입력(영상 다운로드·webhook)에 대해 IP 검증(메타데이터/인코딩 우회 차단) 및 공개 IP 리졸브 검사를 백그라운드 워커에서 수행(요청 핸들러 블로킹 방지).
- **비식별**: 의료영상 3D 메시 생성은 지오메트리만 추출하며 DICOM 태그를 임베드하지 않고 임시 파일을 폐기한다.

## 9. 신뢰성·운영 (Reliability & Operations)

- **무중단 운영**: graceful drain(재시작 시 구독자 종료 통지·스레드 회수), 워커 주기 리사이클.
- **자동 복구**: watchdog(systemd + cron) 기반 자동 재기동 및 포렌식 덤프.
- **동시성 안정화**: SSE 구독자 상한·IP당 1개 축출, SQLite WAL·busy_timeout 일관화.
- **관측성**: Prometheus 메트릭(큐·토큰·엔진 상태·모델별 처리량), 통합 대시보드.
- **회귀 테스트**: 다수의 자동화 테스트(단위·DB 동시성·fork 가드)로 배포 전 검증.

## 10. 책임 있는 AI / 한계 (Responsible AI)

- **의료 AI는 자문 보조 도구**이며, **실시간 처방 차단 시스템이 아니다**. 모든 의료 응답에는 면책 고지를 강제하며, **최종 판단은 처방의·약사 등 의료 전문가**에게 있다.
- 약물 상호작용·금기 정보는 식약처 정본에 근거하나, 환자 개별 상태에 대한 임상 판단을 대체하지 않는다.
- AI 생성 콘텐츠는 표시·서명되며, 생성물의 정확성은 보장 대상이 아니다.

### 10.1 의료기기 규제 대응 (MFDS LLM Guideline Readiness)

식약처 「LLM 기반 디지털의료기기 허가·심사 가이드라인」(안내서-1511-01, 2026-06)에
대응하는 심사 지원 체계를 갖추고 있다(허가 주체는 응용 어플리케이션 측):

- **근거 무생성 보장**: 의료·의료법 응답의 인용(citations/sources)은 전부 실재 DB
  검색 산출물이며, LLM이 인용 문자열을 생성하는 경로가 없다.
- **모델 판본 고정·투명성**: 모델은 태그+digest로 판본 식별, 교체는 릴리즈 단위
  (자동 갱신 없음)·사전 통보. 자체 파인튜닝 모델은 모델 카드 공개
  (`docs/model-cards/` — 학습 데이터 구성·한계 명시).
- **파라미터 재현성**: OpenAI 호환 경로에서 temperature·top_p·max_tokens·seed를
  호출자가 완전 통제(허가 자료의 비교 기준선 재현 조건). 정책 정본
  `docs/LLM_PARAMS_CONTEXT_POLICY.md`.
- **라우팅 구조 보장**: 허가 대상 기능 경로에 자체 개발 모델이 관여하지 않도록
  하는 설정 스위치(`medical_pin_public_models`)를 제공한다.
- **시판 후 품질 모니터링**: 야간 자동 충실도 평가(주장 단위 judge + 검증 특화 모델
  교차검증)와 품질 종합 지수 임계 경보 — 가이드라인이 인정하는 "시판 후 품질
  모니터링 보조 수단" 범주로 운용하며, 단독 성능 검증으로 사용하지 않는다.
- **컨텍스트 초과 = 오류 반환**: 입력 초과 시 무성 절단 없이 실패로 드러난다
  (임상 정보 무성 누락 클래스의 구조적 배제).
